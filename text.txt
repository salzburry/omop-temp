
The deliverable is this file plus **`R/rdq1_cohort1.R`** (dbplyr over ODBC to Databricks, no Spark).
This doc covers what the code does: cohorts, the attrition funnel, code lists, staging and
biomarker matching, how to run it, and questions for Optum.

- **Deployment:** `hive_metastore.clnprw_optum_mc_full_use`, tables `t_*_2025q4`.
- **Study window:** 01-Jan-2020 → 31-Dec-2025. **Product:** Optum Market Clarity, Enhanced Oncology.
- **Counts** are not asserted here — run `rdq1_run(con)` in Databricks to produce them.
- **One external dependency:** `createInPersonalSchema()` (prod-provided), used only when
  `materialize = TRUE` writes the final-step (step 8) tables.

---

## 1. Cohorts and tables

The deliverable is one **Table 1** with **five cohorts**. Each cohort is a **population gate** — which
data assets a patient is present in. The label does *not* restrict which sources feed a step: steps 1-4
read EHR; steps 5-8 (stage, biomarker) read **Enriched Oncology + EHR for every cohort**.

| Cohort | Definition | Membership gate | EO record required? |
|---|---|---|---|
| **Cohort 1** | EHR + notes | `has_notes='Y'` | no |
| **Cohort 2** | + linked **Optum** claims | `has_notes='Y' & market_clarity='Y' & integrated='Y'` | no |
| **Cohort 3** | + linked **3rd-party** claims | `has_notes='Y' & market_clarity='Y' & integrated='N'` | no |
| **Cohort 4** | Cohort 3 + Enriched Oncology | Cohort 3 gate **&** has an EO record | yes |
| **Cohort 5** | Cohort 2 + Enriched Oncology | Cohort 2 gate **&** has an EO record | yes |

- **Claims linkage is membership only** — in the primary run no clinical event is read from claims tables
  (the `io_claims` sensitivity in §6 is the one opt-in exception). Cohorts 2/3 are subsets of Cohort 1
  (same EHR ascertainment, narrower by linkage) and are disjoint (`integrated` Y vs N).
- **"+ Enriched Oncology" is a membership gate, not a data switch.** Cohorts 4/5 additionally require an
  Enriched-Oncology record (`t_onc_neoplasm_histology`). `t_patient` has no EO flag (its `idn_indicator` is
  the Integrated Delivery Network flag, unrelated), so EO presence = an EO record. The gate applies to the
  whole funnel, so Cohort 4 ⊆ Cohort 3 and Cohort 5 ⊆ Cohort 2 at every step.
- **EO is read for all cohorts at steps 5-8.** But qualifying stage/biomarker essentially need EO data, so
  a cohort's staged patients are almost all EO-present — Cohort 3 ≈ Cohort 4 and Cohort 2 ≈ Cohort 5 from
  step 5 on. The EO-membership gate mostly bites at steps 1-4.
- **Expected QC relationships:** Cohort 1 ≥ Cohort 2 and Cohort 1 ≥ Cohort 3 at every step; Cohort 4 ≤
  Cohort 3 and Cohort 5 ≤ Cohort 2 at every step (they are EO subpopulations).

Flags: `MARKET_CLARITY=Y` = has linked claims; `INTEGRATED=Y` = Optum claims (3rd-party = `MC=Y &
INTEGRATED=N`). Notes gate is `HAS_NOTES` (patient has a note), not `NOTES_ELIGIBLE` (source could
supply one). Membership uses linked-claim availability (`MARKET_CLARITY`/`INTEGRATED`), not insurance
enrollment — `ELIGIBILITY` is a separate flag, not required here.

## 2. Datasets used

Patient key = `ptid`. Enriched-onc tumor key = `neoplasm_histology_key`.

- **EHR structured:** `t_patient` (spine + flags), `t_diagnosis`, `t_procedure`, `t_lab`,
  `t_administrations`, `t_prescription`.
- **Physician-notes NLP:** `t_biomarker`.
- **Enriched Oncology (steps 5-8, all cohorts; also the EO-membership gate for Cohorts 4/5):**
  `t_onc_neoplasm_histology` (colon-tumor keys + EO membership), `t_onc_tnm`, `t_onc_stage`,
  `t_onc_lymph_node`, `t_onc_biomarker`.

Databricks returns column names UPPERCASE; `mc_tbl()` lowercases them. All date columns are real
`Date` type.

## 3. The attrition funnel

Per-patient anchors: `surgery_date` (Step 1, = index) · `colon_dx_date` (Step 2) · `mets_date`
(Step 3, right bound for Step 4). Steps 1-4 read EHR; steps 5-8 read enriched oncology + EHR — for every
cohort (the cohort is a population gate, not a per-step source switch).

RDQ criterion 6 (dMMR/MSI-H) is split into three readings, so the funnel has eight rows. Steps 6-8
share one value classification and differ only on the mutation arm: step 6 = any MMR mutation (Optum
§4.1.3), step 7 = pathogenic/positive/present mutation, step 8 = tumor status only, no mutation
(closest to the RDQ; the final cohort). So step 8 ⊆ 7 ⊆ 6.

**Step 1 — Colon cancer surgery (EHR).**
`t_procedure`, `proc_code =` surgery list (§4), in window. Index = the earliest colectomy with a new
colon dx in its 183-day lookback (Step 2 picks it), not just the earliest colectomy — so an unrelated
early one can't set the index.

**Step 2 — Newly diagnosed colon cancer ≤183 d before surgery (EHR).**
`t_diagnosis`, `diagnosis_cd =` colon set (ICD-10, un-dotted, C181 excluded),
`diag_date = [surgery−183, surgery]`. "Newly diagnosed" = earliest colon dx in that window. No lower
date bound — the 183-day window is the only floor, so a late-2019 dx for an early-2020 surgery counts.

**Step 3 — No metastatic diagnosis before surgery (EHR exclusion).**
Mets = `t_diagnosis` C77/C78/C79 or `t_procedure` G9087/G9088 (M1), patient-level (any secondary
neoplasm, not just colon). Exclude if earliest mets is before surgery; keep if no mets, or earliest is
on/after surgery. No lower date bound, so a pre-2020 mets also
excludes. `mets_date` = earliest mets, the Step-4 right bound.

**Step 4 — IO use before the metastatic diagnosis (EHR).**
IO from `t_procedure` (J-codes) + `t_administrations` + `t_prescription`, matched on `generic_desc`
(LIKE IO stems) or `ndc`. Window: `io_date = [colon_dx_date, mets_date)`, capped at study end — strictly
before mets, on/after the colon dx. The colon-dx floor is requestor-confirmed (it keeps out IO given for
another cancer). No surgery constraint — IO can fall before or after surgery. Dates:
`t_prescription → rxdate`; `t_administrations → coalesce(order_date, admin_date)` (anchor on
`order_date`; `ADMIN_DATE` is often null and differs from order).

**Step 5 — Stage T1-4 N1-2, or T4 N0 (Enriched oncology + EHR).**
Qualifying stage: `T=1-4 & N=1-2`, or `T=4 & N=0`. **Same sources for every cohort** — the EHR
disease-status G-codes **G9085** (T4N0) / **G9086** (T1-4N1-2), unioned with three enriched-oncology
sources:
  1. **`t_onc_tnm`** — qualify on the rule above, reading the **first character** of T and N (so T4a, N2b
     collapse to their parent).
  2. **`t_onc_stage`** (AJCC group) — qualify if **Stage III** (arabic `3*` / roman `iii*`) or **Stage
     IIB/IIC** (= T4 N0). Stage IIA/II (T3 N0) and free text (`"advanced"`, `"extensive stage"`) don't map.
  3. **Lymph-node footnote (part of the RDQ criterion).** The RDQ reads *"T1-4 N1-2\* or T4N0 (\* in
     absence of N staging, no. of lymph nodes is >0)"*. So a colon TNM row with T=1-4 and **N absent**
     (null/blank/`Nx`) qualifies when the patient has a positive node —
     `t_onc_lymph_node.lymph_narrative = 'positive lymph node'`. `lymph_numeric` is **not** used on its
     own (the dictionary says it counts positive **or negative or biopsied** nodes); we add
     `lymph_numeric > 0` only as a guard when a count is present. `t_onc_lymph_node` has no tumor key, so
     it matches by `ptid`.

The G-codes are rare (~10-100 rows in the whole database), so staging is effectively EO-driven: a patient
with **no** EO record contributes almost nothing at step 5, which is why the EO-membership gate barely
changes Cohort 3→4 / Cohort 2→5 from here on.

The keyed tables (`t_onc_tnm`, `t_onc_stage`) tie to the patient's colon tumors on **(ptid,
neoplasm_histology_key)**, so staging lands on the colon primary, not another. Patient-level: any of the
patient's colon tumors, not the exact surgical one. No lower date bound (patient-level "ever").

Two additions beyond the literal criterion, both open questions for Optum (§7):
- **Orphan (null-key) rows — `stage_mode`, default `"A"`.** ~70% of `t_onc_tnm` rows (and `t_onc_stage`)
  have a null key and are dropped by the tie above. Mode `"A"` (production) keeps colon-key-linked rows
  only; mode `"C"` also counts orphan rows for single-colon-primary patients, per Optum guide §4.3. Same
  handling for both keyed tables (`rdq1_colon_attributed`).
- **`stage_prefix` (clinical vs pathological) not filtered** — we accept either.

**Steps 6-8 — dMMR+ or MSI-H (Enriched oncology + EHR).**
The RDQ says only **"dMMR+ or MSI-H"** — a positive direction (deficient / high), no value list, no
mention of mutations. **Step 8 answers it directly:** dMMR+/MSI-H by tumor status (MSI / MMR-deficient /
protein-loss), no mutation arm. That's the final cohort — closest to the RDQ, the most defensible number.

Steps 6 and 7 add an MMR-mutation arm on top (Optum §4.1.3 infers dMMR/MSI-H from an MMR mutation; the
RDQ itself doesn't):
- **Step 6** — any MMR mutation, incl. an unqualified `"mutation"` (broadest; the literal Optum rule).
- **Step 7** — only a `pathogenic`/`positive`/`present` mutation. The 6→7 drop is the patients who
  qualified only via an unqualified mutation.

`phenotype ⊆ strict ⊆ inclusive`, so **step 8 ⊆ 7 ⊆ 6**. The 6/7-vs-8 gap is MMR gene-mutation records —
`t_onc_biomarker` or a `t_lab` `gene.mutation` test (pathogenic/positive/present). Widest in the EO cohorts
(4/5), but a non-EO cohort can still show a small gap from `t_lab`.

Common to all three:
- **Sources.** `t_biomarker` (notes NLP) + `t_lab` + `t_onc_biomarker` (enriched onc), read for every
  cohort. Using both `t_onc_biomarker` and `t_lab` follows the guide (§4.1). `t_biomarker` is near-empty for
  MSI/MMR, so a non-EO patient's capture is effectively `t_lab`.
- **Patient-level ("ever")**, not window-bounded — MSI-H/dMMR is a stable tumor/germline trait.
- Value classification and the two flagged calls (negative IHC = loss; "MMR positive"/"detected" = dMMR on
  the system marker only) are in §5. `modifier_narrative` is not consulted — on 2025q4 its only values are
  extent/intensity (partial/focal/weak/…), never negating.

## 5. Staging and biomarker matching detail

### Staging (Step 5) — which T/N qualify

Reading the first character of T and of N:

| T | N | Qualifies? | Rule |
|---|---|---|---|
| 1/2/3 | 1 or 2 | yes | node-positive |
| 4 | 1 or 2 | yes | node-positive |
| 4 | 0 | yes | T4N0 |
| 1/2/3 | 0 | no | node-negative, not T4 |
| 1/2/3/4 | blank / Nx | only if a positive lymph node exists | N-absent footnote |
| Tis / T0 | any | no | not an invasive T1-4 |

### Biomarker (Steps 6-8)

The RDQ asks for **dMMR+ or MSI-H**. It gives no value list, so we map result strings to "positive"
ourselves (Optum §4.1.1 leaves this to the user). Values below are from the observed data (`MSI.txt` =
`t_lab`, `biomarker_tnm_queries.txt` = `t_onc_biomarker`).

A patient is positive if any arm matches (marker name + result value):

| Arm | Marker | Positive result values |
|---|---|---|
| MSI-High | `MSI` / `microsatellite instability` (not `MSS`) | high, positive |
| MMR deficient | `mismatch repair` / `(MMR)` system marker | deficient, loss, loss of expression, positive, detected |
| Protein loss | `MLH1`/`MSH2`/`MSH6`/`PMS2` antigen (not a `mutation` test) | lost, loss, loss of expression, absent, no expression, not expressed, negative |

`t_lab` matches the same way; its dMMR-deficiency panel also uses `abnormal`. Excluded everywhere:
proficient / intact / expressed / retained, MSS / stable, MSI-low, `not detected`, any `no loss…`, and
`VUS` / `benign`.

Two value calls to flag:
- **Negative IHC = loss.** On a protein antigen test, `negative` = no staining = protein lost = dMMR.
  Gated off `gene.mutation` tests, where `negative` = *no mutation found* (not a loss).
- **"MMR positive" / "detected" = dMMR** on the *system* marker only. On a specific protein antigen,
  `positive` = protein present = proficient, so it's excluded.

**This table = the RDQ answer (step 8).** Matching these arms with no mutation genotype is dMMR+/MSI-H by
tumor status — the RDQ criterion, and the final reported cohort.

**Additional — MMR mutations (steps 6/7, beyond the RDQ).** The RDQ never mentions mutations; Optum §4.1.3
infers dMMR/MSI-H from an MMR mutation. We show that as two readings *above* step 8:
- Step 6 — plus **any** MMR mutation (incl. an unqualified `mutation`).
- Step 7 — plus only a **pathogenic/positive/present** mutation.

Step 8 ⊆ 7 ⊆ 6, a clean funnel. The 6/7-vs-8 gap is MMR gene-mutation records — `t_onc_biomarker` or a
`t_lab` `gene.mutation` test — widest in the EO cohorts (4/5), but a non-EO cohort can still show a small
gap from `t_lab`.

## 6. How to run

**As a script (`Rscript`):**
```sh
Rscript R/rdq1_cohort1.R                       # Table 1 (all 5 cohorts), persists final-step (step 8) tables
RDQ1_MATERIALIZE=0 Rscript R/rdq1_cohort1.R    # same, but do NOT persist tables
RDQ1_FAST=0 Rscript R/rdq1_cohort1.R           # disable the temp-table speed-up
```
Per-step counts stream to stderr (`[Cohort 5 | ...] step 5 n=...`); the stacked
Table 1 prints to stdout.

**Interactively:**
```r
source("R/rdq1_cohort1.R")
con <- mc_connect()
rdq1_run(con)                                  # Table 1 — all five cohorts
rdq1_run(con, cohorts = c("Cohort 4","Cohort 5"))  # a subset (by label or key "c4"/"c5")
rdq1_run(con, materialize = TRUE, replace = TRUE)  # + persist final-step (step 8) tables to osk02156
res <- rdq1_run(con); rdq1_table1_wide(res)    # reshape long output to the wide Table-1 shell
rdq1_biomarker_values(con)                     # dump candidate MSI/MMR value strings to eyeball
rdq1_stage_mode_impact(con)                    # step-5 patients added by mode C (orphan rows) over mode A
rdq1_io_funnel_diag(con)                       # decompose the step 3->4 (IO) drop: any IO / after dx / before mets
rdq1_io_claims_impact(con)                      # SENSITIVITY: step-4 patients gained by adding claims IO, per cohort
rdq1_run(con, stage_mode = "C")                # whole Table 1 under mode C instead of the mode-A default
rdq1_run(con, io_claims = TRUE)                # SENSITIVITY Table 1: step 4 adds claims IO (deviates from EHR-only RDQ)
```
The stacked (long) frame `rdq1_run()` returns has one row per step per cohort; `rdq1_table1_wide()`
pivots it to the five-column Table-1 shell (steps as rows, cohorts as columns).

Config at the top of `R/rdq1_cohort1.R`: `RDQ1_STUDY_START/END`, `RDQ1_DX_WINDOW_DAYS=183`,
`RDQ1_REQUIRE_NOTES`, the code-list vectors, and the biomarker status vectors. Env toggles:
`RDQ1_MATERIALIZE=0`, `RDQ1_FAST=0`.

**`materialize` caveat (prod helper).** `createInPersonalSchema()` checks whether a table exists under
`DOMINO_USER_NAME` but creates/replaces under `DOMINO_STARTING_USERNAME`. If those two differ,
`replace = FALSE` can check a different schema than it writes to. This affects only table persistence
(`materialize = TRUE`), never the counts — flag it to the prod file's owner if your environment sets the
two variables differently. A sensitivity run (`stage_mode = "C"` or `io_claims = TRUE`) persists under
suffixed names (`rdq1_<cohort>_modeC` / `_ioclaims`), so it never overwrites the primary `rdq1_<cohort>`
tables.

## 7. Questions for Optum

Data and methodology questions to raise with Optum before locking counts. Our current handling is noted.

**Staging (step 5)**
1. **Orphan (null-key) TNM/stage rows.** ~70% of `t_onc_tnm` rows have no tumor key. Your guide (§4.3)
   calls these "orphan" records and recommends using them for single-cancer patients. For a
   single-colon-primary patient, do you recommend attributing orphan staging to the colon tumor? (We can
   run it either way — `stage_mode` A vs C.)
2. **Clinical vs pathological stage.** We accept either `stage_prefix`. For a surgical cohort, do you
   recommend restricting to pathological (`pTNM`)?
3. **Ever-staged vs stage-at-diagnosis.** We count "ever" T1-4 N1-2 / T4 N0 (patient-level). Your guide
   (§4.3.2) describes stage *at diagnosis* via `neoplasm_dx_date`. Which do you recommend here?
4. **Lymph-node field.** The RDQ footnote uses "no. of lymph nodes >0". We read it from
   `lymph_narrative = 'positive lymph node'`, not `lymph_numeric` (the dictionary says that field counts
   positive **or negative or biopsied** nodes). Which field/value should represent positive nodes?
5. **`t_onc_stage` free text.** The `stage` column mixes AJCC groups with descriptive text ("advanced",
   "extensive stage") and stray m-codes. We map only AJCC groups (III, IIB/IIC). Should any of the
   free-text values map to a TNM stage?
6. **Staging tie.** We tie staging to *any* of the patient's colon tumors on
   `(ptid, neoplasm_histology_key)`, not the exact surgical tumor (a tighter tie drops ~6x of staged
   patients). Do you recommend a stricter tie?

**Biomarker (dMMR / MSI-H)**
7. **MMR mutations in the definition.** The RDQ says only "dMMR+ or MSI-H"; your guide (§4.1.3) infers
   dMMR/MSI-H from an MMR mutation. Do you recommend including MMR gene mutations in the cohort, or
   restricting to tumor status (IHC/MSI)? (We show both.)
8. **"MMR positive" / "detected".** On the `DNA mismatch repair (MMR)` system marker, does
   `narrative_result = 'positive'`/`'detected'` mean deficiency-positive (dMMR)? We count it as dMMR; on a
   specific protein antigen we treat `positive` as protein present (proficient) and exclude it. Please
   confirm.
9. **Patient-level "ever".** dMMR/MSI-H counts patient-level and isn't tied to the colon tumor (the lab/NLP
   tables have no tumor key). Is patient-level "ever" the right approach for a stable trait?
10. **Planned tests.** We exclude `biomarker_temporal_status = 'plan'` (a planned order, not a result) and
    keep current/history/null. Confirm.

**Cohort / population**
11. **Incident vs recent diagnosis.** "Newly diagnosed" is a C18 code within 183 days before surgery, with
    no washout for an earlier diagnosis. Do you recommend a washout / first-ever definition?
12. **Enrollment flags.** Membership uses `MARKET_CLARITY` / `INTEGRATED` (linked-claims availability), not
    `ELIGIBILITY` (enrollment). For a claims-linked cohort, should membership require `ELIGIBILITY`?
13. **Enriched-Oncology membership.** `t_patient` has no EO flag (`idn_indicator` is the Integrated
    Delivery Network flag, unrelated), so we define "has Enriched Oncology" — the Cohort 4/5 gate — as ≥1
    record in `t_onc_neoplasm_histology`. Is that the right EO-membership definition, or is there a
    patient-level EO flag we should use instead?
14. **IO ascertained from EHR only.** Per the RDQ, step 4 (IO) reads EHR sources only — claims-recorded IO
    is excluded, which materially lowers the count (checkpoint inhibitors are heavily claims-billed, and
    most colon IO is metastatic-setting, which the pre-mets window also excludes). We can add claims IO as
    a labeled sensitivity — `rdq1_run(io_claims = TRUE)`, with `rdq1_io_claims_impact()` reporting the
    per-cohort gain. For the linked cohorts (2–5), should IO be ascertained from claims, or stay EHR-only?

**Dates / data**
15. **IO exposure date.** For `t_administrations`, we anchor exposure on `ORDER_DATE` (`ADMIN_DATE` is often
    null). Confirm `ORDER_DATE` is the right exposure date.
16. **AJCC edition.** The enriched TNM tables don't store the AJCC edition (7th vs 8th); our first-char T/N
    rule ignores it. Does the edition affect how we should read T/N?

## 8. Sanity checks for a new data cut

The matching relies on a few data properties. If the `2025q4` tables are swapped for a newer cut,
re-run these:

```sql
-- TNM stored as bare numbers (the code reads the first char of t/n). Expect '3','1','4a','x' — NOT 'T3'/'N1'.
SELECT DISTINCT t, n, m FROM t_onc_tnm_2025q4 LIMIT 50;

-- Biomarker temporal status — the step 6-8 EO arm excludes planned tests. Confirmed on 2025q4 the values
-- are current / null / history / plan; the filter drops 'plan' (166,153 rows / 66,694 pts). Re-check on
-- a new cut and update RDQ1_BIOMARKER_NOT_PLANNED if the deployed value differs.
SELECT biomarker_temporal_status, COUNT(*) n FROM t_onc_biomarker_2025q4
GROUP BY biomarker_temporal_status ORDER BY n DESC;

-- Biomarker vocab (calibrates the step 6-8 status lists). Or call rdq1_biomarker_values(con) from R.
SELECT biomarker, narrative_result, count(*) n FROM t_onc_biomarker_2025q4
WHERE upper(biomarker) RLIKE 'MSI|MICROSATELLITE|MMR|MISMATCH|MLH1|MSH2|MSH6|PMS2'
GROUP BY biomarker, narrative_result ORDER BY n DESC LIMIT 80;

-- Cohort flags present and populated.
SELECT market_clarity, integrated, count(*) n FROM t_patient_2025q4 GROUP BY market_clarity, integrated;

-- (Optional / informational) Histology-key uniqueness. The staging tie joins on
-- (ptid, neoplasm_histology_key), so it does not rely on this; zero rows just confirms keys are unique.
SELECT neoplasm_histology_key, COUNT(DISTINCT ptid) n_pts
FROM t_onc_neoplasm_histology_2025q4 GROUP BY neoplasm_histology_key HAVING COUNT(DISTINCT ptid) > 1 LIMIT 10;
```

# sensitivity, which adds claims IO at step 4:
#   claims 1  = has_notes='Y'
#   claims 2a = has_notes='Y' & market_clarity='Y' & integrated='Y'   (Optum claims)
#   claims 3  = has_notes='Y' & market_clarity='Y' & integrated='N'   (3rd-party claims)
# "+ Enriched Oncology" (Cohorts 4/5) is a population gate: the patient has an EO record
# (t_onc_neoplasm_histology). t_patient has no EO flag (idn_indicator is the Integrated Delivery Network
# flag, unrelated). The gate applies to the whole funnel, so Cohort 4 ⊆ Cohort 3 and Cohort 5 ⊆ Cohort 2.
#
# IE criteria and sources (updated RDQ):
#   1. (EHR)       colon cancer surgery
#   2. (EHR)       newly diagnosed colon cancer within 183 days before surgery
#   3. (EHR)       no metastatic diagnosis before surgery
#   4. (EHR)       IO use, on/after the colon dx and before mets (before or after surgery)
#   5. (EO + EHR)  stage T1-4N1-2 or T4N0
#   6. (EO + EHR)  dMMR or MSI-H — Optum §4.1.3 reading (phenotype + ANY MMR mutation)
#   7. (EO + EHR)  dMMR or MSI-H — strict (MMR mutation pathogenic/positive/present)
#   8. (EO + EHR)  dMMR or MSI-H — tumor status only, no mutation genotype (closest to RDQ; final)
# Criterion 6 in the RDQ is ONE criterion ("dMMR+ or MSI-H"). Steps 6-8 are three readings of it that
# share the value classification and differ only on the mutation arm: 6 counts any MMR mutation
# (Optum §4.1.3), 7 requires a pathogenic/positive/present mutation, 8 drops the mutation genotype the
# RDQ never mentions. phenotype ⊆ strict ⊆ inclusive, so step 8 ⊆ 7 ⊆ 6. The 6/7-vs-8 gap = MMR
# gene-mutation records (t_onc_biomarker OR a t_lab gene.mutation test); widest in the EO cohorts (4/5),
# but a non-EO cohort can still show a small gap from t_lab.
#
# Notes:
#   - Index = earliest colectomy with a new colon dx in the 183 days before it.
#   - Dates: only step 1 (surgery) is bounded to [2020, 2025]. dx, mets, stage and biomarker have no
#     lower bound (all history up to the data cut). So a late-2019 dx within 183 days of an early-2020
#     surgery counts, and a pre-2020 mets/stage still applies.
#   - Stage (onc_tnm + onc_stage, plus a positive-lymph-node rule and G-codes) ties to any of the
#     patient's colon tumors on (ptid, neoplasm_histology_key) — the shared key in both tables.
#     Patient-level, not the strict pre-op tumor.
#   - Mets exclusion is patient-level: any C77-79 before surgery excludes.
#   - Biomarker is patient-level ("ever"); planned t_onc_biomarker tests are dropped.
#   - All cohorts require notes (has_notes = 'Y').
# ============================================================================

MC_CATALOG <- "hive_metastore"

# Open the ODBC connection. Password from an env var, never hard-coded. bigint = "numeric" so
# counts come back as numbers, not integer64 (which breaks the arithmetic later).
mc_connect <- function(dsn     = Sys.getenv("DATABRICKS_DSN", "RWDE"),
                       pwd     = Sys.getenv("DATABRICKS_PWD", ""),
                       timeout = 120,
                       bigint  = "numeric",
                       ...) {
  if (!nzchar(pwd)) stop("DATABRICKS_PWD is not set.")
  DBI::dbConnect(odbc::odbc(), dsn = dsn, pwd = pwd, timeout = timeout, bigint = bigint, ...)
}

# Lazy handle to a table: mc_tbl(con, "diagnosis") -> t_diagnosis_2025q4. Databricks returns columns
# in UPPERCASE, so lowercase them to match the field names below.
mc_tbl <- function(con, name) {
  dplyr::tbl(con, dbplyr::in_catalog(MC_CATALOG, MC_SCHEMA, paste0("t_", name, "_", MC_CUT))) |>
    dplyr::rename_with(tolower)
}

# Distinct-ptid count from a lazy tbl.
n_ptid <- function(tb) {
  tb |> dplyr::summarise(n = dplyr::n_distinct(ptid)) |> dplyr::pull(n) |> as.integer()
}

# Build an OR of LIKE '%...%' checks as raw SQL (Databricks can't push a regex-OR).
rdq1_like_any <- function(col, substrs) {
  terms <- paste0("UPPER(", col, ") LIKE '%", toupper(gsub("'", "''", substrs)), "%'")
  paste0("(", paste(terms, collapse = " OR "), ")")
}

# IO match as raw SQL: drug-name column(s) LIKE any IO stem, optionally OR NDC. LIKE (not ==) because
# the name can carry brand/formulation text. include_ndc = FALSE for tables with no `ndc` column.
rdq1_io_predicate <- function(name_cols, include_ndc = TRUE) {
  name_pred <- paste(vapply(name_cols, function(cc) rdq1_like_any(cc, RDQ1_IO_GENERIC),
                            character(1)), collapse = " OR ")
  if (!include_ndc) return(paste0("(", name_pred, ")"))
  ndc_pred <- paste0("ndc IN ('", paste(RDQ1_IO_NDC, collapse = "','"), "')")
  paste0("(", name_pred, " OR ", ndc_pred, ")")
}

# dMMR/MSI-H positive test as raw SQL. The status word lists are arguments so each table can pass its
# own vocab (defaults for t_onc_biomarker/t_biomarker; RDQ1_LAB_* for t_lab). bcol = marker column,
# scol = status column.
rdq1_dmmr_msi_predicate <- function(bcol, scol,
                                    msi_pos   = RDQ1_MSI_POS_STATUS,
                                    mmr_def   = RDQ1_MMR_DEF_STATUS,
                                    prot_loss = RDQ1_PROT_LOSS_STATUS,
                                    mut_pos   = RDQ1_MMR_MUT_POS,
                                    inclusive = FALSE, mutation = TRUE) {
  U   <- function(x) paste0("upper(", x, ")")
  inl <- function(col, vals) paste0("lower(", col, ") IN (",
           paste0("'", tolower(gsub("'", "''", vals)), "'", collapse = ","), ")")
  is_msi  <- paste0("(", U(bcol), " LIKE '%MICROSATELLITE INSTABILITY%' OR ", U(bcol), " LIKE '%MSI%')")
  is_mss  <- paste0("(", U(bcol), " LIKE '%MICROSATELLITE STABLE%' OR ", U(bcol), " LIKE '%MSS%')")
  is_mmr  <- paste0("(", U(bcol), " LIKE '%MISMATCH REPAIR%' OR ", U(bcol), " LIKE '%(MMR)%')")
  is_prot <- paste0("(", paste(sprintf("%s LIKE '%%%s%%'", U(bcol),
                     c("MLH1","MSH2","MSH6","PMS2")), collapse = " OR "), ")")
  has_mut <- paste0("(", U(bcol), " LIKE '%MUTATION%')")   # a gene-mutation test (vs an antigen/IHC test)
  # MMR gene-mutation test: a "*MUTATION*" test of an MMR gene, positive/pathogenic/present. Gating on
  # MUTATION keeps it off the antigen/MSI tests, where "positive" means the opposite.
  is_mut  <- paste0("(", has_mut, " AND (", is_mmr, " OR ", is_prot, "))")
  # Protein IHC loss. Gate to NON-mutation tests so a "negative" gene-mutation result (= no mutation, not a
  # loss) can't count via prot_loss; on antigen/IHC tests "negative" = negative staining = loss.
  prot_ihc <- paste0("(", is_prot, " AND NOT ", has_mut, ")")
  # Standalone MMR-deficiency marker ("DNA mismatch repair (MMR)" / dMMR panel): "positive"/"detected"
  # = deficiency-positive = dMMR+ (the marker is the MMR system, not a specific protein), so count it
  # (RDQ "dMMR+" literally). Gated off is_prot so a PMS2 antigen "positive" (protein PRESENT = proficient,
  # the OPPOSITE) does NOT leak in. Phenotype arm -> present in all readings incl. step 8.
  mmr_only <- paste0("(", is_mmr, " AND NOT ", is_prot, ")")
  mmr_pos_arm <- paste0(" OR (", mmr_only, " AND ", inl(scol, c("positive", "detected")), ")")
  # mutation = FALSE drops the genotype (mutation) arms entirely -> the RDQ-as-worded phenotype only
  # (dMMR+ / MSI-H = MSI-High OR MMR-deficient OR MMR-protein loss; the RDQ never mentions mutations).
  # mutation = TRUE keeps the strict mutation arm (pathogenic/positive/present); inclusive additionally
  # counts an unqualified 'mutation' narrative (Optum §4.1.3 literal).
  mut_arm <- if (mutation) paste0(" OR (", is_mut, " AND ", inl(scol, mut_pos), ")") else ""
  extra   <- if (mutation && inclusive)
    paste0(" OR ((", is_mmr, " OR ", is_prot, ") AND ", inl(scol, "mutation"), ")") else ""
  paste0("( (", is_msi, " AND NOT ", is_mss, " AND ", inl(scol, msi_pos), ")",
         " OR (", is_mmr, " AND ", inl(scol, mmr_def), ")",
         " OR (", prot_ihc, " AND ", inl(scol, prot_loss), ")",
         mmr_pos_arm, mut_arm, extra, " )")
}

# ============================================================================
# 3. PER-CRITERION BUILDERS  (each returns a lazy tbl)
#    Steps 1-4 read EHR; steps 5-8 read EHR + Enriched Oncology, for EVERY cohort. The cohort label is a
#    population gate, not a per-step source restriction.
# ============================================================================

# Enriched-Oncology membership: a patient "has EO" if they appear in the EO neoplasm table. t_patient
# carries no EO flag (idn_indicator is the Integrated Delivery Network flag, unrelated), so EO presence
# is an EO record. Cohorts 4/5 add this gate — it is the only thing separating them from Cohorts 3/2.
rdq1_eo_member_pts <- function(con)
  mc_tbl(con, "onc_neoplasm_histology") |> dplyr::distinct(ptid)

# Cohort POPULATION gate. Notes for every cohort; the claims-linkage flags narrow 2a/3; `eo` adds the
# EO-record gate for Cohorts 4/5. Claims flags are used ONLY here (membership) — in the primary run no
# clinical event is read from claims tables (the io_claims sensitivity is the exception). The gate applies
# to the whole funnel (steps 1-8), so an EO cohort is narrower from step 1, not only at staging.
rdq1_cohort_pts <- function(con, claims, eo = FALSE) {
  p <- mc_tbl(con, "patient")
  if (RDQ1_REQUIRE_NOTES)  p <- p |> dplyr::filter(has_notes == "Y")
  if (claims == "2a")      p <- p |> dplyr::filter(market_clarity == "Y", integrated == "Y")
  else if (claims == "3")  p <- p |> dplyr::filter(market_clarity == "Y", integrated == "N")
  pts <- p |> dplyr::distinct(ptid)
  if (eo) pts <- pts |> dplyr::semi_join(rdq1_eo_member_pts(con), by = "ptid")
  pts
}

# Colon tumor keys (any colon neoplasm) + their patient. Ties stage to the colon cancer, not another
# primary. Carries `ptid` so the staging join is on (ptid, neoplasm_histology_key) — the shared key,
# present in both t_onc_tnm and t_onc_neoplasm_histology (varlist) — not the key alone.
rdq1_colon_neo_keys <- function(con)
  mc_tbl(con, "onc_neoplasm_histology") |>
    dplyr::filter(dbplyr::sql(rdq1_like_any("neoplasm_type", RDQ1_COLON_NEO_SUBSTR)),
                  neoplasm_qualifier == "actual") |>
    dplyr::distinct(ptid, neoplasm_histology_key)

# Single-colon-primary patients — used by stage_mode "C" to decide who may claim orphan (null-key) rows
# in t_onc_tnm and t_onc_stage.
# Optum Enriched Oncology guide §4.3: orphan stage records can be attributed to the one cancer for a
# single-primary patient; for multiple primaries, corroborate. The guide (§4.2.2, §4.4.3) says make that
# call from the structured Diagnosis table / ICD codes. §4.2 warns the enriched neoplasm_type
# over-fragments one real cancer. So use ICDs, not neoplasm_type.
# Single colon primary = a colon primary dx (C18.x) and no other primary-cancer ICD (any C-code that is
# not colon and not secondary/mets C77-79/C7B). Mets don't disqualify (they're secondary codes).
rdq1_single_colon_primary <- function(con) {
  dx <- mc_tbl(con, "diagnosis") |>
    dplyr::filter(diagnosis_cd_type == "ICD10", diag_date <= RDQ1_STUDY_END)
  colon <- dx |>
    dplyr::filter(substr(diagnosis_cd, 1, 3) %in% RDQ1_COLON_ICD3) |>
    dplyr::distinct(ptid)
  other_primary <- dx |>
    dplyr::filter(substr(diagnosis_cd, 1, 1) == "C",
                  !(substr(diagnosis_cd, 1, 3) %in% RDQ1_COLON_ICD3),
                  !(substr(diagnosis_cd, 1, 3) %in% RDQ1_SECONDARY_ICD3)) |>
    dplyr::distinct(ptid)
  dplyr::anti_join(colon, other_primary, by = "ptid")
}

# Restrict an enriched-onc staging table (t_onc_tnm / t_onc_stage — both carry ptid + note_date +
# neoplasm_histology_key) to the patient's colon tumor(s), per stage_mode. Mode A: colon-key-linked rows
# only. Mode C: also orphan (null-key) rows for single-colon-primary patients (Optum guide §4.3). Same
# handling for both tables so TNM and stage-group are attributed identically.
rdq1_colon_attributed <- function(con, tbl, stage_mode) {
  keyed <- dplyr::semi_join(tbl, rdq1_colon_neo_keys(con), by = c("ptid", "neoplasm_histology_key"))
  if (stage_mode == "A") return(keyed)
  orphan <- tbl |>
    dplyr::filter(is.na(neoplasm_histology_key) | neoplasm_histology_key == "") |>
    dplyr::semi_join(rdq1_single_colon_primary(con), by = "ptid")
  dplyr::union_all(keyed, orphan)
}

# Step 1 — colon surgery (EHR only). Every qualifying surgery date per patient; the orchestrator
# picks the index.
rdq1_surgery <- function(con) {
  mc_tbl(con, "procedure") |>
    dplyr::filter(proc_code %in% RDQ1_SURG_CODES,
                  proc_date >= RDQ1_STUDY_START, proc_date <= RDQ1_STUDY_END) |>
    dplyr::transmute(ptid, surgery_date = proc_date) |>
    dplyr::distinct()
}

# Step 2 — colon dx (EHR only): ICD-10 colon codes. No lower bound — the orchestrator keeps only dx in
# the 183 days before surgery, so a late-2019 dx for an early-2020 surgery still counts. Upper bound =
# data-cut ceiling.
rdq1_colon_dx <- function(con) {
  mc_tbl(con, "diagnosis") |>
    dplyr::filter(diagnosis_cd_type == "ICD10", diagnosis_cd %in% RDQ1_DX_ICD,
                  diag_date <= RDQ1_STUDY_END) |>
    dplyr::transmute(ptid, dx_date = diag_date)
}

# Step 3 helper — earliest mets per patient (EHR only): ICD C77-79 + the M1 G-codes. No lower bound —
# criterion 3 has no lookback limit, so a pre-2020 mets can exclude an in-window surgery. Patient-level
# (any C77-79). The orchestrator drops a patient whose earliest mets is before surgery.
rdq1_mets <- function(con) {
  m_icd <- mc_tbl(con, "diagnosis") |>
    dplyr::filter(diagnosis_cd_type == "ICD10", substr(diagnosis_cd, 1, 3) %in% RDQ1_METS_ICD3,
                  diag_date <= RDQ1_STUDY_END) |>
    dplyr::transmute(ptid, mets_date = diag_date)
  m_g <- mc_tbl(con, "procedure") |>
    dplyr::filter(proc_code %in% RDQ1_METS_G,
                  proc_date <= RDQ1_STUDY_END) |>
    dplyr::transmute(ptid, mets_date = proc_date)
  dplyr::union_all(m_icd, m_g) |>
    dplyr::group_by(ptid) |>
    dplyr::summarise(mets_date = min(mets_date, na.rm = TRUE), .groups = "drop")
}

# Step 4 — IO use. EHR (RDQ-faithful): J-codes in t_procedure + generic-name matches in
# t_administrations and t_prescription. Returns ptid + io_date; the date window is applied in the
# orchestrator. use_claims = TRUE is a SENSITIVITY ONLY (the RDQ is EHR-only): it also adds IO from
# claims — t_clm_rx (PAID, gnrc_nm/ndc) + t_clm_med_services (J-codes/ndc). Off by default.
rdq1_io <- function(con, use_claims = FALSE) {
  proc <- mc_tbl(con, "procedure") |>
    dplyr::filter(proc_code %in% RDQ1_IO_JCODE) |> dplyr::transmute(ptid, io_date = proc_date)
  # Anchor exposure on order_date (admin_date is frequently null in t_administrations and differs from
  # order_date); fall back to admin_date only if order_date is null.
  adm <- mc_tbl(con, "administrations") |>
    dplyr::filter(dbplyr::sql(rdq1_io_predicate("generic_desc"))) |>
    dplyr::transmute(ptid, io_date = dplyr::coalesce(order_date, admin_date))
  presc <- mc_tbl(con, "prescription") |>
    dplyr::filter(dbplyr::sql(rdq1_io_predicate("generic_desc"))) |>
    dplyr::transmute(ptid, io_date = rxdate)
  io <- dplyr::union_all(dplyr::union_all(proc, adm), presc)
  if (use_claims) {
    # clm_rx: generic name or NDC, PAID only (rejected/reversed were never dispensed).
    rx <- mc_tbl(con, "clm_rx") |>
      dplyr::filter(transaction_type == "PAID", dbplyr::sql(rdq1_io_predicate("gnrc_nm"))) |>
      dplyr::transmute(ptid, io_date = fill_dt)
    # clm_med_services: infused IO via J-code or NDC. paid_status is almost all null, so not filtered.
    svc <- mc_tbl(con, "clm_med_services") |>
      dplyr::filter(proc_cd %in% RDQ1_IO_JCODE | ndc %in% RDQ1_IO_NDC) |>
      dplyr::transmute(ptid, io_date = fst_dt)
    io <- dplyr::union_all(dplyr::union_all(io, rx), svc)
  }
  io
}

# Step 5 — stage T1-4N1-2 or T4N0 (RDQ criterion 5). EHR G-codes UNION the enriched-onc staging tables,
# read for every cohort. No lower bound (patient-level, so a pre-2020 stage counts); upper = data-cut ceiling.
# Three enriched sources, unioned with the G-codes:
#   1. t_onc_tnm  — (T1-4 & N1-2) OR (T4 & N0), on the first char of T/N so T4a/N2b collapse.
#   2. lymph node — RDQ footnote "in absence of N staging, no. of lymph nodes is >0": a colon TNM row with
#      T1-4 and N absent (null/blank/Nx) plus a POSITIVE lymph node. Positivity from lymph_narrative;
#      lymph_numeric alone is ambiguous (dict: positive OR negative OR biopsied nodes), so require
#      lymph_numeric > 0 only as a guard when a count is present. Part of the criterion, not a toggle.
#      t_onc_lymph_node has no tumor key, so the node is matched by ptid.
#   3. t_onc_stage — AJCC stage group: Stage III (node-positive) or IIB/IIC (T4 N0). Same colon tie.
# stage_mode ties the two keyed tables (t_onc_tnm, t_onc_stage) to the colon tumor on (ptid,
# neoplasm_histology_key). ~70% of rows have a NULL key — "orphan" records per the Optum guide §4.3.
#   "A" (default): colon-key-linked rows only. Orphans dropped. Safest; may under-count stage.
#   "C": mode A PLUS orphan rows for single-colon-primary patients (the guide's recommendation).
# NOTE: stage_prefix (clinical vs pathological) is NOT filtered — open question for the requestor/Optum.
rdq1_stage_ok <- function(con, stage_mode = c("A", "C")) {
  stage_mode <- match.arg(stage_mode)
  g <- mc_tbl(con, "procedure") |>
    dplyr::filter(proc_code %in% RDQ1_STAGE_G_QUALIFY,
                  proc_date <= RDQ1_STUDY_END) |>
    dplyr::distinct(ptid)

  # 1 + 2 — t_onc_tnm. rename n -> n_val (n clashes with dplyr::n()); first char of T and N.
  tnm <- rdq1_colon_attributed(con, mc_tbl(con, "onc_tnm") |>
                                 dplyr::filter(note_date <= RDQ1_STUDY_END), stage_mode) |>
    dplyr::rename(n_val = n) |>
    dplyr::mutate(t1 = substr(t, 1, 1), n1 = substr(n_val, 1, 1))
  rule_tnm <- tnm |>
    dplyr::filter((t1 %in% c("1","2","3","4") & n1 %in% c("1","2")) |
                  (t1 == "4" & n1 == "0")) |> dplyr::distinct(ptid)
  # RDQ footnote — N absent + positive lymph node stands in for N1-2.
  tnm_nabsent <- tnm |>
    dplyr::filter((is.na(n_val) | n_val == "" | tolower(n_val) == "x") &
                  t1 %in% c("1","2","3","4")) |> dplyr::distinct(ptid)
  ln_pos <- mc_tbl(con, "onc_lymph_node") |>
    dplyr::filter(dbplyr::sql(
      "lower(lymph_narrative) LIKE '%positive lymph node%' AND (lymph_numeric IS NULL OR lymph_numeric > 0)"),
                  note_date <= RDQ1_STUDY_END) |>
    dplyr::distinct(ptid)
  rule_node <- dplyr::inner_join(tnm_nabsent, ln_pos, by = "ptid")

  # 3 — t_onc_stage. AJCC group: Stage III (arabic "3*"/roman "iii*") or IIB/IIC.
  stg <- rdq1_colon_attributed(con, mc_tbl(con, "onc_stage") |>
                                 dplyr::filter(note_date <= RDQ1_STUDY_END), stage_mode) |>
    dplyr::mutate(s = tolower(stage))
  rule_stage <- stg |>
    dplyr::filter(substr(s, 1, 1) == "3" | substr(s, 1, 3) == "iii" |
                  s %in% RDQ1_STAGE_T4N0) |> dplyr::distinct(ptid)

  Reduce(dplyr::union, list(g, rule_tnm, rule_node, rule_stage))
}

# Step 6 — dMMR/MSI-H. Sources: t_biomarker (notes NLP) + t_lab + t_onc_biomarker (enriched onc), read
# for every cohort. Patient-level "ever" (MSI-H/dMMR is a stable trait), so not window-bounded.
# The three readings share the SAME positive-value classification (MSI-High / MMR-deficient / protein
# loss). They differ ONLY in the mutation-genotype arm. The RDQ says nothing about mutations; that comes
# from Optum §4.1.3. The orchestrator runs all three as steps 6-8:
#   "inclusive" (step 6) — Optum §4.1.3 literal: phenotype + ANY MMR mutation (incl. an unqualified
#      t_onc_biomarker narrative_result = 'mutation').
#   "strict"    (step 7) — phenotype + MMR mutation only if pathogenic/positive/present.
#   "phenotype" (step 8) — tumor status only (MSI-H / MMR-deficient / protein loss); NO mutation arm.
#      Closest to the RDQ wording ("dMMR+ or MSI-H"). phenotype ⊆ strict ⊆ inclusive.
rdq1_biomarker <- function(con, mode = c("strict", "inclusive", "phenotype")) {
  mode <- match.arg(mode)
  incl <- mode == "inclusive"; mut <- mode != "phenotype"
  pred <- function(b, s, ...) rdq1_dmmr_msi_predicate(b, s, ..., inclusive = incl, mutation = mut)
  nlp <- mc_tbl(con, "biomarker") |>
    dplyr::filter(dbplyr::sql(pred("biomarker", "biomarker_status"))) |>
    dplyr::distinct(ptid)
  lab <- mc_tbl(con, "lab") |>   # t_lab uses its own vocab (LOST/INTACT/...); pass RDQ1_LAB_* sets
    dplyr::filter(dbplyr::sql(pred("test_name", "test_result",
                   RDQ1_LAB_MSI_POS, RDQ1_LAB_MMR_DEF, RDQ1_LAB_PROT_LOSS))) |>
    dplyr::distinct(ptid)
  # Enriched-onc biomarker (read for every cohort; patients with no EO record contribute no rows). Drop
  # planned tests: biomarker_temporal_status = 'plan' is an order, not a result. Keep current/history/null.
  onc <- mc_tbl(con, "onc_biomarker") |>
    dplyr::filter(dbplyr::sql(pred("biomarker", "narrative_result")),
                  dbplyr::sql(RDQ1_BIOMARKER_NOT_PLANNED)) |>
    dplyr::distinct(ptid)
  dplyr::union(dplyr::union(nlp, lab), onc)
}

# ============================================================================
# 4. ORCHESTRATOR
# ============================================================================
# Steps 1-4 are EHR-only; steps 5-8 read Enriched Oncology + EHR. Both run over the cohort's population
# gate — the cohort label is a population, not a per-step source restriction, so EO is read for everyone.

# EHR funnel (steps 1-4), gated to this cohort's population (a lazy tbl of ptids). Returns the step tbls.
rdq1_ehr_steps <- function(con, cohort_pts, cmp, use_claims = FALSE) {
  # Step 1 — surgeries, gated to this cohort's population.
  s1 <- cmp(rdq1_surgery(con) |>
              dplyr::semi_join(cohort_pts, by = "ptid"))

  # Step 2 — index = earliest colectomy with a colon dx in its 183-day window. Pair each surgery with
  # the dx (restricted to surgery patients), keep in-window pairs, take the earliest such surgery + dx.
  dx <- cmp(rdq1_colon_dx(con) |> dplyr::semi_join(s1, by = "ptid"))
  pairs <- cmp(s1 |>
    dplyr::inner_join(dx, by = "ptid") |>
    dplyr::filter(dx_date <= surgery_date,
                  datediff(surgery_date, dx_date) <= RDQ1_DX_WINDOW_DAYS))
  idx_surg <- pairs |>
    dplyr::group_by(ptid) |>
    dplyr::summarise(surgery_date = min(surgery_date, na.rm = TRUE), .groups = "drop")
  s2 <- cmp(pairs |>
    dplyr::inner_join(idx_surg, by = c("ptid", "surgery_date")) |>
    dplyr::group_by(ptid, surgery_date) |>
    dplyr::summarise(colon_dx_date = min(dx_date, na.rm = TRUE), .groups = "drop"))

  # Step 3 — exclude any metastatic diagnosis before surgery. Keep patients with no mets, or whose
  # earliest mets is on/after surgery. Carry mets_date forward for the IO window.
  mets <- cmp(rdq1_mets(con) |> dplyr::semi_join(s2, by = "ptid"))
  s3 <- cmp(s2 |>
    dplyr::left_join(mets, by = "ptid") |>
    dplyr::filter(is.na(mets_date) | mets_date >= surgery_date))

  # Step 4 — IO before mets (before OR after surgery). io_date floored at the colon dx (so IO for another
  # cancer doesn't count), capped at study end, and strictly before mets if a mets date exists. Collapse
  # to one row per patient.
  io <- cmp(rdq1_io(con, use_claims) |> dplyr::semi_join(s3, by = "ptid"))
  s4 <- cmp(s3 |>
    dplyr::inner_join(io, by = "ptid") |>
    dplyr::filter(io_date >= colon_dx_date, io_date <= RDQ1_STUDY_END,
                  is.na(mets_date) | io_date < mets_date) |>
    dplyr::distinct(ptid, surgery_date, colon_dx_date, mets_date))

  list(s1 = s1, s2 = s2, s3 = s3, s4 = s4)
}

# Enriched-onc funnel (steps 5-8), over the step-4 survivors. stage_mode "A"/"C" goes to rdq1_stage_ok.
# Biomarker is a three-step funnel on one criterion: step 6 = inclusive (Optum §4.1.3, any MMR mutation),
# step 7 = narrow to pathogenic/positive/present mutation, step 8 = tumor status only (no mutation
# genotype = closest to the RDQ wording). phenotype ⊆ strict ⊆ inclusive, so s8 ⊆ s7 ⊆ s6. A cohort with
# no EO members contributes no onc rows, so its 5-8 come only from G-codes / t_lab / notes NLP.
rdq1_onc_steps <- function(con, s4, cmp, stage_mode = "A") {
  stg <- cmp(rdq1_stage_ok(con, stage_mode = stage_mode) |> dplyr::semi_join(s4, by = "ptid"))
  s5  <- cmp(s4 |> dplyr::semi_join(stg, by = "ptid"))
  s6  <- cmp(s5 |> dplyr::semi_join(rdq1_biomarker(con, "inclusive"), by = "ptid"))
  s7  <- cmp(s6 |> dplyr::semi_join(rdq1_biomarker(con, "strict"),    by = "ptid"))
  s8  <- cmp(s7 |> dplyr::semi_join(rdq1_biomarker(con, "phenotype"), by = "ptid"))
  list(s5 = s5, s6 = s6, s7 = s7, s8 = s8)
}

RDQ1_STEP_LABELS <- c(
  "1. Colon cancer surgery",
  "2. Newly diagnosed colon cancer within 183d prior to surgery",
  "3. No metastatic diagnosis prior to surgery",
  "4. IO use prior to metastatic diagnosis (before or after surgery)",
  "5. Stage T1-4N1-2 or T4N0",
  "6. dMMR+ or MSI-H — Optum §4.1.3 (incl. any MMR mutation)",
  "7. dMMR+ or MSI-H — strict (MMR mutation pathogenic/positive/present)",
  "8. dMMR+ or MSI-H — tumor status only, no mutation (closest to RDQ)")

# Turn the step tbls into the attrition data frame (and optionally persist the final step). `key`/`label`/
# `basis` name the cohort (e.g. "c4" / "Cohort 4" / "EHR + notes + 3rd-party claims + Enriched Oncology").
rdq1_build_table <- function(key, label, basis, steps, verbose = TRUE,
                             materialize = FALSE, replace = FALSE, name_suffix = "") {
  n <- integer(length(steps))
  for (i in seq_along(steps)) {
    n[i] <- n_ptid(steps[[i]])
    if (verbose) {
      message(sprintf("[%s | %s] step %d  n=%s", label, basis, i, format(n[i], big.mark = ",")))
    }
  }
  out <- data.frame(
    cohort = label, basis = basis, step = seq_along(steps),
    criterion = RDQ1_STEP_LABELS, n = n,
    pct_step1 = round(100 * n / n[1], 1),
    pct_prev  = round(100 * n / c(n[1], head(n, -1)), 1),
    stringsAsFactors = FALSE)
  if (materialize) {
    # createInPersonalSchema() uses the global `con` and writes to osk02156. Make sure con is set.
    # Persist the FINAL step (step 8 = tumor-status dMMR/MSI-H, the RDQ-closest cohort). name_suffix
    # keeps a sensitivity run (mode C / io_claims) from overwriting the primary rdq1_<cohort> tables.
    # It is "" for the default run, so those names are unchanged.
    createInPersonalSchema(steps[[length(steps)]], paste0("rdq1_", key, name_suffix), replace = replace)
  }
  out
}

# fast = TRUE: write each step to a temp table (compute()) and restrict the next heavy scan to patients
# still in the funnel. This stops the lazy per-step counts from re-running the whole chain. Results are
# identical to fast = FALSE (the restrictions are semi-joins the funnel already applies). Set FALSE if
# the warehouse rejects temp tables.

# One attrition table for a single ad-hoc population (claims gate + optional EO gate). rdq1_run produces
# the official five-cohort Table 1.
rdq1_attrition_table <- function(con, claims = c("1", "2a", "3"), eo = FALSE,
                                 stage_mode = "A", io_claims = FALSE,
                                 materialize = FALSE, replace = FALSE, verbose = TRUE, fast = TRUE) {
  claims <- match.arg(claims)
  cmp <- function(x) if (fast) dplyr::compute(x) else x
  ehr <- rdq1_ehr_steps(con, rdq1_cohort_pts(con, claims, eo), cmp, io_claims)
  onc <- rdq1_onc_steps(con, ehr$s4, cmp, stage_mode)
  steps <- list(ehr$s1, ehr$s2, ehr$s3, ehr$s4, onc$s5, onc$s6, onc$s7, onc$s8)
  tag <- paste0(claims, if (eo) "_eo" else "")
  sfx <- paste0(if (stage_mode != "A") paste0("_mode", stage_mode) else "", if (io_claims) "_ioclaims" else "")
  rdq1_build_table(paste0("m", tag), paste0("claims ", claims, if (eo) " + EO" else ""),
                   "(ad-hoc single funnel)", steps, verbose, materialize, replace, sfx)
}

# The deliverable. Run Table 1 (five cohorts) and stack them. Each cohort is its own population (claims
# gate + EO gate), so its funnel is built independently. `cohorts` picks a subset by label ("Cohort 4")
# or key ("c4"). io_claims = TRUE is the SENSITIVITY (adds claims IO at step 4; the primary run is
# EHR-only, per the RDQ).
rdq1_run <- function(con, cohorts = RDQ1_TABLE1$label, stage_mode = "A", io_claims = FALSE,
                     materialize = FALSE, replace = FALSE, verbose = TRUE, fast = TRUE) {
  spec <- RDQ1_TABLE1[RDQ1_TABLE1$label %in% cohorts | RDQ1_TABLE1$key %in% cohorts, , drop = FALSE]
  if (nrow(spec) == 0L)
    stop("No matching cohorts. Use labels (\"Cohort 1\"..\"Cohort 5\") or keys (\"c1\"..\"c5\").")
  cmp <- function(x) if (fast) dplyr::compute(x) else x
  # A sensitivity run gets its own materialized table names so it can't overwrite the primary outputs.
  sfx <- paste0(if (stage_mode != "A") paste0("_mode", stage_mode) else "", if (io_claims) "_ioclaims" else "")
  do.call(rbind, lapply(seq_len(nrow(spec)), function(i) {
    pts <- rdq1_cohort_pts(con, spec$claims[i], spec$eo[i])
    ehr <- rdq1_ehr_steps(con, pts, cmp, io_claims)
    onc <- rdq1_onc_steps(con, ehr$s4, cmp, stage_mode)
    steps <- list(ehr$s1, ehr$s2, ehr$s3, ehr$s4, onc$s5, onc$s6, onc$s7, onc$s8)
    rdq1_build_table(spec$key[i], spec$label[i], spec$basis[i], steps, verbose, materialize, replace, sfx)
  }))
}

# Reshape the long attrition frame (from rdq1_run) into the wide Table-1 shell: one row per step,
# one column per cohort. Default shows n; pass value="pct_step1"/"pct_prev" for the percentage views.
rdq1_table1_wide <- function(res, value = c("n", "pct_step1", "pct_prev")) {
  value <- match.arg(value)
  steps <- unique(res[order(res$step), c("step", "criterion")])
  cohorts <- unique(res$cohort)
  for (co in cohorts) {
    sub <- res[res$cohort == co, ]
    steps[[co]] <- sub[[value]][match(steps$step, sub$step)]
  }
  steps
}

# Diagnostic: how many patients stage_mode "C" ADDS at step 5 over mode "A", inside the real funnel (the
# two EO cohorts). Mode A stages on colon-key-linked rows only; mode C also counts orphan (null-key) rows
# (t_onc_tnm + t_onc_stage) for single-colon-primary patients (Optum guide §4.3).
#   rdq1_stage_mode_impact(mc_connect())
rdq1_stage_mode_impact <- function(con, fast = TRUE) {
  cmp  <- function(x) if (fast) dplyr::compute(x) else x
  spec <- RDQ1_TABLE1[RDQ1_TABLE1$eo, ]   # the EO-member cohorts: Cohort 4 (claims 3), Cohort 5 (claims 2a)
  do.call(rbind, lapply(seq_len(nrow(spec)), function(i) {
    ehr <- rdq1_ehr_steps(con, rdq1_cohort_pts(con, spec$claims[i], spec$eo[i]), cmp)
    s4  <- ehr$s4
    stg_a <- cmp(rdq1_stage_ok(con, stage_mode = "A") |> dplyr::semi_join(s4, by = "ptid"))
    stg_c <- cmp(rdq1_stage_ok(con, stage_mode = "C") |> dplyr::semi_join(s4, by = "ptid"))
    n_a <- n_ptid(s4 |> dplyr::semi_join(stg_a, by = "ptid"))
    n_c <- n_ptid(s4 |> dplyr::semi_join(stg_c, by = "ptid"))
    data.frame(cohort               = spec$label[i],
               step4                = n_ptid(s4),
               step5_colon_linked   = n_a,        # mode A (production)
               step5_single_primary = n_c,        # mode C (+ orphans, single colon primary)
               added_by_orphans     = n_c - n_a,
               stringsAsFactors = FALSE)
  }))
}

# Diagnostic: decompose the step 3 -> step 4 (IO) drop for a cohort's population. A big drop is expected —
# pre-mets IO in a curative colon population is clinically rare, AND step 4 is EHR-only, so IO recorded
# only in claims is excluded by design. This shows where patients go: step-3 survivors -> those with ANY
# IO record in EHR -> IO on/after the colon dx -> IO strictly before mets (= step 4). If any_io_ever is
# already tiny, the limiter is EHR capture / drug matching (not the window); if the drop is mostly at
# io_before_mets_s4, the pre-mets filter removes them (post-mets / palliative IO).
#   rdq1_io_funnel_diag(mc_connect())                 # Cohort 1 population
#   rdq1_io_funnel_diag(mc_connect(), claims = "2a")  # Cohort 2 / 5 population
rdq1_io_funnel_diag <- function(con, claims = "1", eo = FALSE, fast = TRUE) {
  cmp <- function(x) if (fast) dplyr::compute(x) else x
  s3  <- rdq1_ehr_steps(con, rdq1_cohort_pts(con, claims, eo), cmp)$s3
  j   <- cmp(s3 |> dplyr::inner_join(rdq1_io(con) |> dplyr::semi_join(s3, by = "ptid"), by = "ptid"))
  win <- j |> dplyr::filter(io_date >= colon_dx_date, io_date <= RDQ1_STUDY_END)
  data.frame(
    step3               = n_ptid(s3),
    any_io_ever         = n_ptid(j),
    io_on_after_colondx = n_ptid(win),
    io_before_mets_s4   = n_ptid(win |> dplyr::filter(is.na(mets_date) | io_date < mets_date)),
    stringsAsFactors = FALSE)
}

# Sensitivity: step-4 patients GAINED by adding claims IO (t_clm_rx PAID + t_clm_med_services J-codes/NDC)
# to the EHR-only ascertainment, per cohort. The RDQ is EHR-only; this quantifies the cost of that
# restriction on the IO criterion. Claims help only where a cohort has linked claims (2/3/4/5); Cohort 1
# gains only from its claims-linked subset. Same step-4 window as the funnel, over the same step-3 survivors.
#   rdq1_io_claims_impact(mc_connect())
rdq1_io_claims_impact <- function(con, fast = TRUE) {
  cmp <- function(x) if (fast) dplyr::compute(x) else x
  s4win <- function(s3, uc) cmp(s3 |>
    dplyr::inner_join(rdq1_io(con, use_claims = uc) |> dplyr::semi_join(s3, by = "ptid"), by = "ptid") |>
    dplyr::filter(io_date >= colon_dx_date, io_date <= RDQ1_STUDY_END,
                  is.na(mets_date) | io_date < mets_date) |>
    dplyr::distinct(ptid))
  do.call(rbind, lapply(seq_len(nrow(RDQ1_TABLE1)), function(i) {
    s <- RDQ1_TABLE1[i, ]
    s3 <- rdq1_ehr_steps(con, rdq1_cohort_pts(con, s$claims, s$eo), cmp)$s3
    n_ehr <- n_ptid(s4win(s3, FALSE)); n_clm <- n_ptid(s4win(s3, TRUE))
    data.frame(cohort = s$label, step4_ehr = n_ehr, step4_ehr_claims = n_clm,
               added_by_claims = n_clm - n_ehr, stringsAsFactors = FALSE)
  }))
}

# ============================================================================
# 5. VALIDATION HELPER — list candidate biomarker values to eyeball
# ============================================================================
rdq1_biomarker_values <- function(con, n = 200) {
  list(
    lab = mc_tbl(con, "lab") |>
      dplyr::filter(dbplyr::sql(rdq1_like_any("test_name", RDQ1_BIOMARKER_NAME_SUBSTR))) |>
      dplyr::count(test_name, test_result, sort = TRUE) |> head(n) |> dplyr::collect(),
    nlp_biomarker = mc_tbl(con, "biomarker") |>
      dplyr::filter(dbplyr::sql(rdq1_like_any("biomarker", RDQ1_BIOMARKER_NAME_SUBSTR))) |>
      dplyr::count(biomarker, biomarker_status, sort = TRUE) |> head(n) |> dplyr::collect(),
    onc_biomarker = mc_tbl(con, "onc_biomarker") |>
      dplyr::filter(dbplyr::sql(rdq1_like_any("biomarker", RDQ1_BIOMARKER_NAME_SUBSTR))) |>
      dplyr::count(biomarker, narrative_result, sort = TRUE) |> head(n) |> dplyr::collect())
}

# ============================================================================
# 6. Rscript entry point
# ============================================================================
# `Rscript rdq1_cohort1.R` runs Table 1 (all five cohorts). When source()d instead, this block does
# nothing (sys.nframe() is 0 only as the top-level script).
# RDQ1_MATERIALIZE=0 skips persisting the final-step (step 8) tables (default: on).
# RDQ1_FAST=0 turns off the temp-table speed-up (default: on).
if (sys.nframe() == 0L && !interactive()) {
  con <- mc_connect()
  mat  <- !identical(Sys.getenv("RDQ1_MATERIALIZE", "1"), "0")
  fast <- !identical(Sys.getenv("RDQ1_FAST", "1"), "0")
  if (mat && !exists("createInPersonalSchema")) {   # don't lose a good run at the persistence step
    message("createInPersonalSchema() is not loaded — running WITHOUT materialize. ",
            "Load the prod personal-schema helper (or set RDQ1_MATERIALIZE=0) to silence this.")
    mat <- FALSE
  }
  res <- rdq1_run(con, materialize = mat, replace = mat, fast = fast)
  print(res[, c("cohort", "step", "criterion", "n", "pct_step1", "pct_prev")], row.names = FALSE)
  # Also print the wide "Table 1" shell (one column per cohort).
  cat("\n== Table 1 (five cohorts) ==\n")
  print(rdq1_table1_wide(res, "n"), row.names = FALSE)
}
