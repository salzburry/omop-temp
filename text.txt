# RDQ 317023 — Colon Cancer / Dostarlimab (AZUR-2) — Cohort Feasibility

The deliverable is this file plus **`R/rdq1_cohort1.R`** (dbplyr over ODBC to Databricks, no Spark).
Everything is here: datasets, cohort rules, per-step logic, code lists, validation results, decisions,
and the SQL to reproduce them (§10). No other file is needed to read or run it. The one outside piece
is `createInPersonalSchema()` — prod provides it, and only when `materialize=TRUE` writes tables (L5).

- **Deployment:** `hive_metastore.clnprw_optum_mc_full_use`, tables `t_*_2025q4` (52 deployed).
- **Study window:** 01-Jan-2020 → 31-Dec-2025. **Product:** Optum Market Clarity, Enhanced Oncology.
- **Discipline:** decisions are grounded in *observed live values*, not the dictionary alone and not
  inference. The data dictionary is authoritative; live sample data validates/observes. Attrition
  **counts are not asserted here** — they require `rdq1_run(con)` in Databricks.
- **Disclosure control:** small-cell suppression `MIN_CELL = 11` (mask N in 1..10).
- **Scope of code:** `R/rdq1_cohort1.R` implements **all cohorts (1 / 2a / 3) × both variants
  (1a / 1b)** — 6 attrition funnels. `rdq1_run(con)` returns all 6; pass `cohorts=`/`variants=` to
  subset (e.g. `rdq1_run(con, cohorts="1")`). Cohorts 2a/3 add the `t_clm_*` claims arms (§3) on top
  of the notes+claims patient gate.
- **`R/rdq1_check_v2_staging.R` and `R/rdq1_diag_q6b.R` are diagnostics, NOT part of the deliverable.**
  `rdq1_check_v2_staging.R` is the **Q6 check** (still open — forces steps 3 & 5 to the enriched-onc
  arm for *both* variants). `rdq1_diag_q6b.R` is the **Q6b check** — Q6b is **already resolved** (prod
  switched to the patient-level tie = its arm B), so this one is historical/re-verification only. Both
  source the main file and are `Rscript`-runnable. Production is still the single `R/rdq1_cohort1.R`;
  delete `rdq1_check_v2_staging.R` once Q6 is decided, and `rdq1_diag_q6b.R` whenever you like.

## 1. Cohort structure

Two orthogonal dimensions produce the RDQ Table 1a / 1b grid.

**Variant (table rows) — 1a vs 1b, additive:**
- **1a = EHR codes + physician-notes NLP + `t_lab`**, no enriched oncology.
- **1b = 1a + enriched-oncology `t_onc_*`** (every 1a source kept, `t_onc_*` on top). So **1b ≥ 1a**
  usually — but not strictly at every step: 1b's extra dx source can move the index surgery earlier,
  which shifts the later windows. The 1a→1b gap = what enriched oncology adds, biggest where codes are
  weak (staging, biomarker).

**Cohort column — 1 / 2a / 3, by claims linkage on `t_patient` (all flags `Y`/`N`, dict-defined):**

| Column | Definition | `t_patient` filter |
|---|---|---|
| **Cohort 1** | EHR + physician notes (claims-agnostic) | `has_notes='Y'` |
| **Cohort 2a** | + linked **Optum** Medical & Rx claims | `has_notes='Y' & market_clarity='Y' & integrated='Y'` |
| **Cohort 3** | + linked **3rd-party** Medical & Rx claims | `has_notes='Y' & market_clarity='Y' & integrated='N'` |

- **Scope = these 3 cohorts only (signed off).** The *clarified* ask defines exactly Cohort 1 / 2a / 3.
  An earlier version of the RDQ form carried a 4th column ("Cohort 4: Market Clarity IHD, closed") —
  that column is **out of scope** and deliberately not implemented, per the clarified ask.
- **Notes gate = `HAS_NOTES`, not `NOTES_ELIGIBLE`.** `t_patient` has both: `NOTES_ELIGIBLE` (1/0 —
  source *can* supply notes) and `HAS_NOTES` (Y/N — patient *has* ≥1 note). They differ. "EHR + notes"
  needs notes present, so gate on `HAS_NOTES='Y'`.
- **Flags:** `MARKET_CLARITY=Y` = has linked claims; `INTEGRATED=Y` = Optum claims (3rd-party =
  `MC=Y & INTEGRATED=N`); `ELIGIBILITY=Y` = enrollment present. Nested `EHR ⊇ MC=Y ⊇ Eligibility=Y ⊇
  Integrated=Y`. Don't confuse `INTEGRATED` (Y/N) with `IDN_INDICATOR` (1/0 — a different column).
- **Monotonicity:** 1a→1b is monotonic on population (same patients, more ascertainment), so 1b ≥ 1a
  usually — not strictly, since the index surgery is picked per variant. Cohort columns 1→2a→3 are
  **not** monotonic — each is its own attrition on its own sub-population.

## 3. Attrition funnel — 6 criteria

Per-patient anchors: `surgery_date` (Step 1, = index) · `colon_dx_date` (Step 2) · `mets_date`
(Step 4, right bound for Step 6). For each step: **1a** (codes-only) · **1b** (adds enriched onc) ·
**claims arm** (added for 2a/3).

**Step 1 — Colon cancer surgery.**
- 1a/1b → `t_procedure`: `proc_code ∈` surgery list (§4), exact match, in study window.
- **Index = earliest DX-LINKED colectomy**, not just the earliest colectomy. The builder returns all
  qualifying surgeries. Step 2 pairs each with the colon dx and picks the earliest surgery that has a
  new colon dx in its 183-day lookback. This stops an unrelated early colectomy from pinning the index
  and dropping the patient (D14).
- claims (2a/3): `t_clm_med_services.proc_cd` (CPT/HCPCS) + `t_clm_med_procedure.proc` (ICD-PCS), date
  `fst_dt`. Inpatient procedures already land in `med_procedure`, so `inpat_confinement` is skipped.

**Step 2 — Newly diagnosed colon cancer ≤183 d before surgery.**
- 1a → `t_diagnosis`: `diagnosis_cd ∈` colon set (un-dotted; **C181 excluded**),
  `diagnosis_cd_type='ICD10'`, `diag_date ∈ [surgery−183, surgery]`. `diagnosis_status` **not**
  filtered (near-uniform "Diagnosis of"; low-information).
- 1b → also `t_onc_neoplasm_histology`: `neoplasm_type ∈ {colon, colorectal, sigmoid, cecum}`
  (substring match; `ascending/transverse/descending colon` already contain "colon"; **`cecum`** is
  a separate term — see Vneo), `neoplasm_qualifier='actual'`, anchor `note_date`.
- claims: `t_clm_med_diagnosis.diag` (colon set), date `fst_dt`. (Inpatient diagnoses already land
  in `med_diagnosis`.)
- "Newly diagnosed" = **earliest colon dx inside `[surgery−183, surgery]`**. Every dx source is bounded
  to `[2020, 2025]` first, then the orchestrator keeps only in-window dx before taking the min. So a
  pre-study (e.g. 2007) claims code can't set the date or exclude the patient (Q1).

**Step 3 — Stage T1–4 N1–2, or T4 N0 (if N absent, node-positive).**
- 1a → `t_procedure` disease-status G-codes: **G9086** (t1-4,n1-2,m0 → T1-4N1-2 ✅), **G9085**
  (t4,n0,m0 → T4N0 ✅); G9084 does not qualify. *(Observed rarity: G9085≈11, G9086≈97 rows total.)*
- 1b → `t_onc_tnm` (`T∈{1-4} & N∈{1,2}` OR `T=4 & N=0`); **N-absent fallback
  `t_onc_lymph_node.lymph_narrative='positive lymph node'`** (NOT `lymph_numeric>0`, which counts
  negatives/examined). **`onc_tnm` is tied to ANY of the patient's colon tumors** (`neoplasm_histology_key`
  ∈ the colon-neoplasm key set) — a **patient-level colon tie**, not the exact index tumor. The tighter
  Optum §4.3.2 episode-key tie was tested and dropped ~5.9× of staged patients to key fragmentation
  (staging sits on the surgical-path key, not the pre-op-note key); for the ~99% single-colon-primary
  patient the two are the same tumor. See §11 Q5/Q6b.
- claims: G9085/G9086 in `t_clm_med_services.proc_cd` **only** — claims carry no structured TNM
  (limitation; notes-gated 2a/3 patients still have EHR/notes staging).
- **All staging sources are bounded to the study window** `[2020, 2025]` (staging is episode-specific;
  a pre-study stage from another cancer must not qualify an in-study patient — D14).

**Step 4 — No metastatic diagnosis before surgery (exclusion).**
- 1a → exclude `t_diagnosis` C77*/C78*/C79* with `diag_date < surgery_date`; also exclude
  `t_procedure` G9087/G9088 (M1).
- 1b → also `t_onc_metastatic_location` (`mets_qualifier='actual'`, `mets_temporal_status='current'`,
  anchor `note_date`) and `t_onc_tnm.m` starting `1` (M1). **Matched PATIENT-LEVEL (not colon-key-
  tied)** — RDQ criterion 4 excludes *any* secondary neoplasm (C77-79), a patient-level rule; tying
  to the colon key would under-exclude. (Contrast step 3, which IS tumor-specific.)
- claims: `t_clm_med_diagnosis.diag` C77-79 (prefix) + `t_clm_med_services.proc_cd` mets G-codes,
  date `fst_dt`. **All mets sources are bounded to the study window** `[2020, 2025]` (so a pre-study
  mets can't wrongly exclude an in-study surgery patient). `mets_date` = earliest in-window mets.

**Step 5 — dMMR+ or MSI-H.**
- MSI/MMR lives in **`t_onc_biomarker`** (enriched onc); `t_biomarker` is ~empty for MSI/MMR.
  - 1a → `t_biomarker` + `t_lab` (4-antibody IHC panel MLH1/PMS2/MSH6/MSH2 ~4,300 each + MSI ~2,600).
  - 1b → adds `t_onc_biomarker` (the real source). No ICD code exists for MSI-H/dMMR.
- **Positive definition** (calibrated to real vocab, see §5 for the observed value sets):
  - MSI-High = `microsatellite instability (MSI)` (not MSS) with `high`/`positive`.
  - MMR deficient = `DNA mismatch repair (MMR)` with `deficient`/`loss`/`loss of expression`.
  - Protein loss = MLH1/MSH2/MSH6/PMS2 with `loss`/`loss of expression`/`absent`/`no expression`/`negative`.
  - `t_lab` vocab is separate (`LOST`=loss; ambiguous `NEGATIVE`/`POSITIVE` excluded on proteins).
- claims (2a/3): small `tst_desc`-conditional arm on `t_clm_lab_results` — **MSI-High** =
  MSI/microsatellite test (`tst_desc` NOT matching `methylation`/`borrelia`/`hermsii`/`mutation`/
  `variant`/`gene`/`without`/`w/o` — those flip the meaning of a POSITIVE) with `rslt_txt ∈
  {POSITIVE, ABNORMAL}`; **MMR-deficient** = MLH1/MSH2/MSH6/PMS2 *IHC* test (`tst_desc` has
  `IHC`/`INTERP`) with `rslt_txt ∈ {NOT EXPRESSED, NOT DETECTED}`. See §5 (V8-A2) for why.
- **Biomarker is matched PATIENT-LEVEL ("ever"), NOT study-window-bounded** (unlike steps 1-4) —
  MSI-H/dMMR is a stable tumor/germline trait, so a valid pre-window test still applies (D17).

**Step 6 — IO use after colon-dx and before mets (claims-agnostic in Cohort 1).**
- 1a → `t_procedure` (HCPCS J-codes) + `t_administrations` + `t_prescription`, matched on
  `generic_desc`/`drug_name` (substring LIKE IO stems) OR `ndc`. Dates: `t_prescription` → `rxdate`;
  `t_administrations` → **`coalesce(admin_date, order_date)`** (ADMIN_DATE frequently NULL).
- 1b → also `t_onc_medications` (`data_source ∈ {proc, provider_notes, rx_adm, rx_presc}` — excludes
  claims sources `clm_med_serv`/`clm_rx`, keeping Cohort 1 claims-agnostic).
- claims (2a/3): `t_clm_rx` (matched on **`gnrc_nm` (substring) OR `ndc`**; `brnd_nm` is *not*
  separately matched — the generic name is reliably populated, and the RDQ IO drugs are IV infusions
  rarely in retail Rx anyway, see §11 Q2; **PAID only** via `transaction_type`) +
  `t_clm_med_services` (`ndc`/`proc_cd` J-codes).
- Window: **`io_date ∈ [colon_dx_date, mets_date)`**, also capped at `RDQ1_STUDY_END` — left-closed
  (same-day-as-dx IO counts as "after dx"), right-open (strictly before mets), and bounded to the
  study window on top like every other event source. Matches the code (`io_date >= colon_dx_date &
  io_date <= RDQ1_STUDY_END & io_date < mets_date`); see §6 D16.

**Tables touched per step:**

| Step | 1a (codes) | 1b (adds enriched onc) | claims arm (2a/3) |
|---|---|---|---|
| spine | `t_patient` | +`has_notes='Y'` gate | (patient-flag gate) |
| 1 surgery | `t_procedure` | (same) | `t_clm_med_services`,`t_clm_med_procedure` |
| 2 dx | `t_diagnosis` | +`t_onc_neoplasm_histology` | `t_clm_med_diagnosis` |
| 3 stage | `t_procedure` G9085/86 | `t_onc_tnm`,`t_onc_lymph_node` | `t_clm_med_services` (G-codes only) |
| 4 no-mets | `t_diagnosis` C77-79 + G9087/88 | +`t_onc_metastatic_location`,`t_onc_tnm` | `t_clm_med_diagnosis` |
| 5 biomarker | `t_lab`,`t_biomarker` | +`t_onc_biomarker` | `t_clm_lab_results` (small) |
| 6 IO | `t_procedure`,`t_administrations`,`t_prescription` | +`t_onc_medications` | `t_clm_rx`,`t_clm_med_services` |

|---|---|---|---|
| MSI = `high` | 48,188 | MSI = `stable` | 105,495 |

wrongly count MSI-`stable` (105k), MMR-`proficient` (24k), and protein-`intact` (~46k each). Legacy
`t_biomarker` had ~no MSI/MMR rows; `null` narrative_result is common (MMR `null` 114,065), not counted.

**V8-A2 interpretable-positive detail** (the only claims-lab rows that count toward step 5; the rest
are placeholders `PRC`/`Comment`/`see note`/`Performed`/`TNP-###`, or negatives `NEGATIVE`/`Normal`/

`MSI,HNPCC` 10, `MSI(H)>BRAF(NEG)>MLH1` 10, `Microsatellite Instab-MSI` 2, `MSI BY PCR…REFLEX` 1;

Trap: `DETECTED`/`Not Detected` on a **mutation/variant** test means the OPPOSITE (negative) → excluded.

## 6. Design decisions (register)

| # | Decision | Rationale |
|---|---|---|
| D1 | 1a/1b additive: 1b ≥ 1a **on population** (step-level not strictly guaranteed — per-variant index can shift, see §1) | RDQ "[from EHR]" tags = which data ascertains, not a different population |
| D2 | Cohorts 1/2a/3 by `t_patient` claims flags | flag semantics (dict + V7) |
| D3 | Notes gate = `HAS_NOTES='Y'` (not `NOTES_ELIGIBLE`) | needs notes present, not merely eligible |
| D4 | Patient-level joins by `ptid` | attrition is patient-level |
| D5 | `onc_tnm` staging tied at **patient-level to any colon tumor** (`neoplasm_histology_key` ∈ colon-neoplasm keys), incl. **cecum** | Q6b: the exact §4.3.2 episode-key tie dropped ~5.9× (key fragmentation, staging on the path key); patient-level colon = same tumor for ~99% single-primary |
| D6 | Mets matched PATIENT-LEVEL, not colon-key-tied | RDQ criterion 4 (C77-79) is patient-level by design |
| D7 | Colon dx = exact-set (C181 excluded); mets = 3-char prefix | RDQ appendix; ICD un-dotted |
| D8 | Biomarker positive rule calibrated per source vocab | lenient matcher would miscount MSI-stable/MMR-proficient |
| D9 | Node fallback = `lymph_narrative='positive lymph node'` | numeric counts negatives/examined too |
| D10 | IO = generic/drug substring OR NDC; admin date = `coalesce(admin_date, order_date)` | brand/formulation text; ADMIN_DATE null |
| D11 | Cohort 1 IO claims-agnostic (`onc_medications.data_source` excludes clm sources) | Cohort 1 is claims-agnostic |
| D12 | Claims hygiene: IO Rx PAID only; claims staging = G-codes only | REJECTED/REVERSED ≠ exposure; claims lack TNM |
| D13 | Step-5 claims-lab arm `tst_desc`-conditional (§3 step 5) | V8-A2: same result string flips meaning by test type |
| D14 | Index = **earliest DX-LINKED colectomy** (earliest colectomy with a newly-dx colon cancer in its 183-day lookback), not the earliest colectomy; "newly dx" = earliest colon dx **inside** [index_surgery−183, index_surgery]; all dx, mets & staging sources bounded to the study window [2020, 2025] | RDQ index blank; recovers patients whose earliest colectomy is unrelated; prevents claims lookback reaching pre-study evidence |
| D15 | `MIN_CELL=11`; materialize to `osk02156` via `createInPersonalSchema()` | disclosure control; personal-schema persistence |
| D16 | IO window = `[colon_dx_date, mets_date)`, capped at `RDQ1_STUDY_END` (same-day-as-dx IO counts; strictly before mets; within study window) | "after dx" read inclusively; mets is the exclusion boundary; every event source bounded to [2020, 2025] |
| D17 | Biomarker (step 5) stays **patient-level "ever"**, NOT study-window-bounded | MSI-H/dMMR is a stable tumor/germline trait; bounding could wrongly exclude a valid pre-window test |
| D18 | A cohort column can dip below another at step 6 (e.g. c2a 1b s6=6 < c1 1b s6=7) — not a bug | 2a/3 add claims mets, so `mets_date` is earlier or equal; the `[dx, mets)` IO window is tighter, so IO after a claims-found mets is (correctly) excluded. Better mets detection → stricter "before mets" |

## 7. dbplyr / execution gotchas (observed live)

1. **Column case** — Databricks returns UPPERCASE; `mc_tbl()` does `rename_with(tolower)`. Raw
   `tbl(con, in_catalog(...))` → `Object 'diagnosis_status' not found`.
2. **`t_onc_tnm`**, not `t_onc_tmm` (typo → table-not-found).
3. **No regex-OR code matching** — `str_detect(x, paste(codes, collapse="|"))` fails ("Only fixed
   patterns are supported on database backends"). Use `%in%`, prefix `LIKE`/`RLIKE`, or a semi-join.
4. **Dates** — `proc_date`/`diag_date`/`note_date`/`action_date` and all claims base dates are real
   `Date`s (+ `*_year/_month/_day`, numeric `*_sasdt` helpers).
5. **Enriched-onc dx dates are strings** — `neoplasm_dx_date`, `metastasis_dx_date` are `YYYYMMDD`,
   possibly partial → prefer `note_date`.
6. **`rslt_nbr` unusable in claims labs** — uniform `0.00`; use `rslt_txt` (§3 step 5).

## 8. How to run

**As a script (`Rscript`) — the file has a guarded entry point that runs the full grid:**
```sh
Rscript R/rdq1_cohort1.R                  # connects, runs all 6 funnels, materializes to personal schema
RDQ1_MATERIALIZE=0 Rscript R/rdq1_cohort1.R   # same, but do NOT persist the step tables

Per-step counts stream to **stderr** (`[c1 1a] step 1 n=...`); the stacked table prints to **stdout**.
The entry point only fires when the file is the top-level script — `source()`ing it (interactively or
from the check scripts) just defines the functions.

**Interactively:**

source("R/rdq1_cohort1.R")               # self-contained: connection + table helpers are included
con  <- mc_connect()                     # global `con` (materialize=TRUE also needs the prod createInPersonalSchema())

```

**Diagnostics (Rscript-runnable, not part of the deliverable):**

## 11. Open questions & known limitations (validation pass)

- **Q1 — "newly diagnosed" × claims lookback (RESOLVED).** Bug: only the surgery builder was
  window-bounded, so the dx/mets builders took `min()` over all history. A 2a/3 claims lookback to
  ~2007 could set `min(dx)`/`min(mets)` before 2020 and wrongly drop a valid patient. Fix:
  `rdq1_colon_dx` and `rdq1_mets` now bound every source to `[2020-01-01, 2025-12-31]`, and step 2
  keeps only colon dx inside `[surgery−183, surgery]` (earliest in-window). So 2007 can't leak in.
  - **Accepted trade-off (mets, step 4):** since mets is also window-bounded, a mets before 2020 does
    not exclude an in-window surgery patient (2019 mets + 2020 surgery → kept). Deliberate — only
    in-study mets can exclude.
- **Q2 — IO via retail pharmacy is ~zero.** The RDQ IO drugs are IV checkpoint inhibitors
  (buy-and-bill infusions), not retail scripts. So the `t_clm_rx` arm catches little; the real claims
  IO signal is `t_clm_med_services` J-codes. The Rx arm is kept (harmless, additive) but low-yield.
- **Q3 — biomarker is patient-level "ever" by design (RESOLVED as D17).** Steps 1-4 and staging are
  study-window-bounded (D14); **biomarker (step 5) is deliberately NOT** — MSI-H/dMMR is a stable
  tumor/germline trait, so a valid pre-window test still applies; bounding it could wrongly exclude.
  IO (step 6) is windowed to `[colon_dx_date, mets_date)` (D16).
- **Q4 — claims diagnoses carry no status.** A work-up/"rule-out" C18 coded on a claim counts as a
  colon dx (claims have no `diagnosis_status`). Inherent claims limitation; the EHR side also does
  not filter status (it's low-information).
- **Q5 — staging (step 3) tie: patient-level colon (RESOLVED — replaced the strict §4.3.2 episode
  tie).** Optum §4.3.2 links Stage/TNM to `t_onc_neoplasm_histology` via `neoplasm_histology_key`. We
  first implemented the strict **episode** tie (onc_tnm restricted to the colon tumor diagnosed in the
  index surgery's 183-day window). **Q6b measured it on live data and it dropped ~5.9× of genuinely
  staged patients** (597 tied vs 3,500 patient-level, cohort 1). Cause = **key fragmentation**: 13,873
  of 19,055 step-2 patients *had* a pre-op colon-neoplasm note, but the staging `onc_tnm` sits on a
  *different* `neoplasm_histology_key` (the surgical-pathology record), so the exact `(ptid, key)` tie
  failed. **Now tied patient-level to any of the patient's colon tumors** (`semi_join(onc_tnm,
  colon-neoplasm keys)` — colon set includes **cecum**), which for the ~99% single-colon-primary patient
  is the same tumor; a rare multi-primary could borrow another colon primary's stage (accepted). G-codes
  and the lymph fallback were already patient-level. `rdq1_colon_neo_dated`/`episode_keys` are no longer
  used by the pipeline (retained only by the `rdq1_diag_q6b` check).
- **Q6 — do steps 3 (Stage) & 5 (biomarker) belong to `1a`, or only `1b`? (OPEN — scoping decision.)**
  Observed in the first run: **`1a` step 3 = 0** for all cohorts (1/2a/3), but **`1b` step 3 is
  healthy** (`c1 1b`=597, `c2a 1b`=681 — *pre-Q6b*; now patient-level, so ~6× higher on the next run).
  The `1a` zero is data reality, not a missing code — `1a`
  staging is only the disease-status G-codes **G9085/G9086**, which cover **~7–14 patients in the
  whole database** (`RDQ/proc and neoplasm.txt`); structured EHR/claims carry no TNM. The RDQ form
  reinforces this — it tags steps 1/2/4/6 as **`[from EHR]`** but **not** step 3 (Stage) or step 5
  (dMMR/MSI-H). Two readings: **(#1, strict / current prod)** `1a` excludes enriched oncology, so `1a`
  step 3 ≈ 0 is a legitimate finding (real numbers live in `1b`); **(#2)** staging/biomarker draw from
  `t_onc_tnm`/`t_onc_biomarker` in *both* tables. `R/rdq1_check_v2_staging.R` implements #2.
  **This is now purely a scoping choice for the requestor** — the `1b` path is confirmed working (NOT
  a bug: independent code re-reads verified the `substr` T/N parse, the `n→n_val` rename, the
  unions, and the 183-day window are all correct against the real `onc_tnm` vocabulary).
  - **Q6b — episode-tie was over-restrictive (RESOLVED → patient-level, see Q5/D5).** The steep `1b`
    step-2→step-3 drop is a data-availability signature: claims inflate step 2 but add **zero** `onc_tnm`
    rows (`c1→c2a` step 2 +46,057 while step 3 moved only +84). The Q6b diagnostic (`R/rdq1_diag_q6b.*`)
    confirmed the exact-key tie was the culprit — **A(episode-tied)=597 vs B(patient-level)=3,500, 5.9×**,
    with `s2`=19,055 and `step3_tied`=597 both reproducing the prod run. Step 3 was switched to the
    patient-level colon tie, so the next run's `1b` step 3 (and the whole downstream funnel) should rise
    ~6×, with the **cecum** fix on top (`cecum`≈23k pts was missing from the colon matcher).
- **L1 — PARTIAL RUN OBSERVED; full validation still pending.** A first `rdq1_run(con)` executed in
  Databricks and returned counts, so the dbplyr→Spark-SQL translation, `datediff`, and union/semi-join
  chains **do run** (no translation error seen). Observed so far: all three `1a` funnels, `c1 1b`
  (full), and `c2a 1b` through step 3. **Still pending:** `c2a 1b` steps 4–6, all of `c3 1b`,
  `rdq1_run_v2(con)`, the Q6/Q6b decision and diagnostic, and a clean final full-grid pass. Treat the
  observed values as a first look — **no counts are asserted in this file.**
- **L2 — masked vs raw N.** `rdq1_run()` output carries both raw `n` and suppressed `n_display`
  (`MIN_CELL=11`). Share `n_display`; treat raw `n` as internal.
- **L3 — `t_clm_rx.ndc` is Char(20)** vs the 11-digit `RDQ1_IO_NDC` list; the `gnrc_nm` substring is
  the primary Rx match, so NDC format mismatch (if any) is low-impact. For the three 5-3-2 agents
  (toripalimab/tislelizumab/cosibelimab) the 10→11-digit padding is ambiguous, so the list carries
  **both** 11-digit forms; confirm the stored form on the instance (`SELECT DISTINCT ndc …`) and prune.
- **L4 — `createInPersonalSchema()` env-var mismatch (affects `materialize=TRUE` only).** The helper
  checks table *existence* against `Sys.getenv("DOMINO_USER_NAME")` but *writes* to

  different schema than the write. Does not affect non-materialized attrition counts. (Helper is a
  shared cross-project utility — flag to its owner; not modified here.)
- **L5 — `materialize=TRUE` needs the prod personal-schema helper.** The pipeline is otherwise fully
  self-contained (the connection + table helpers are inlined in `R/rdq1_cohort1.R`); the only external
  dependency is `createInPersonalSchema()`, supplied by the production environment, and it is invoked
  only when persisting step tables. Non-materialized `rdq1_run(con)` has no external dependency.

# Open the ODBC connection to the Databricks SQL warehouse. Token comes from an env var,
# never hard-coded. bigint = "numeric" so COUNT/aggregates don't come back as integer64
# (which breaks masking arithmetic downstream).
mc_connect <- function(dsn     = Sys.getenv("DATABRICKS_DSN", "RWDE"),
                       pwd     = Sys.getenv("DATABRICKS_PWD", ""),
                       timeout = 120,
                       bigint  = "numeric",
                       ...) {
  if (!nzchar(pwd)) stop("DATABRICKS_PWD is not set.")
  DBI::dbConnect(odbc::odbc(), dsn = dsn, pwd = pwd, timeout = timeout, bigint = bigint, ...)
}

# Lazy handle to a deployed table: mc_tbl(con, "diagnosis") -> t_diagnosis_2025q4.
# Databricks returns columns UPPERCASE and dbplyr's name check is case-sensitive, so we
# lowercase them to match the lowercase field names used throughout the pipeline.
mc_tbl <- function(con, name) {
  dplyr::tbl(con, dbplyr::in_catalog(MC_CATALOG, MC_SCHEMA, paste0("t_", name, "_", MC_CUT))) |>
    dplyr::rename_with(tolower)
}

# Small-cell masking for display: true 0 kept; 1..MIN_CELL-1 -> "<MIN_CELL"; NA -> "n/a".
mc_mask <- function(n) {
  dplyr::case_when(
    is.na(n)             ~ "n/a",
    n > 0 & n < MIN_CELL ~ paste0("<", MIN_CELL),
    TRUE                 ~ as.character(as.integer(n))
  )
}

# Distinct-ptid count from a lazy tbl.
n_ptid <- function(tb) {
  tb |> dplyr::summarise(n = dplyr::n_distinct(ptid)) |> dplyr::pull(n) |> as.integer()
}

# Build an OR of LIKE '%...%' checks as raw SQL. Databricks can't push a regex-OR, so we write it out.
rdq1_like_any <- function(col, substrs) {
  terms <- paste0("UPPER(", col, ") LIKE '%", toupper(gsub("'", "''", substrs)), "%'")
  paste0("(", paste(terms, collapse = " OR "), ")")
}

# IO match as raw SQL: drug-name column(s) LIKE any IO stem, optionally OR NDC in the list. We use
# LIKE (not ==) because the name can carry brand/formulation text. Set include_ndc = FALSE for tables
# with no `ndc` column (e.g. t_onc_medications) so we don't reference a missing column.
rdq1_io_predicate <- function(name_cols, include_ndc = TRUE) {
  name_pred <- paste(vapply(name_cols, function(cc) rdq1_like_any(cc, RDQ1_IO_GENERIC),
                            character(1)), collapse = " OR ")
  if (!include_ndc) return(paste0("(", name_pred, ")"))
  ndc_pred <- paste0("ndc IN ('", paste(RDQ1_IO_NDC, collapse = "','"), "')")
  paste0("(", name_pred, " OR ", ndc_pred, ")")
}

# dMMR/MSI-H positive test as raw SQL. The status word lists are arguments so each table can use its
# own vocabulary (t_onc_biomarker/t_biomarker by default; pass the RDQ1_LAB_* lists for t_lab).
# bcol = marker-name column, scol = status column.
rdq1_dmmr_msi_predicate <- function(bcol, scol,
                                    msi_pos   = RDQ1_MSI_POS_STATUS,
                                    mmr_def   = RDQ1_MMR_DEF_STATUS,
                                    prot_loss = RDQ1_PROT_LOSS_STATUS) {
  U   <- function(x) paste0("upper(", x, ")")
  inl <- function(col, vals) paste0("lower(", col, ") IN (",
           paste0("'", tolower(gsub("'", "''", vals)), "'", collapse = ","), ")")
  is_msi  <- paste0("(", U(bcol), " LIKE '%MICROSATELLITE INSTABILITY%' OR ", U(bcol), " LIKE '%MSI%')")
  is_mss  <- paste0("(", U(bcol), " LIKE '%MICROSATELLITE STABLE%' OR ", U(bcol), " LIKE '%MSS%')")
  is_mmr  <- paste0("(", U(bcol), " LIKE '%MISMATCH REPAIR%' OR ", U(bcol), " LIKE '%(MMR)%')")
  is_prot <- paste0("(", paste(sprintf("%s LIKE '%%%s%%'", U(bcol),
                     c("MLH1","MSH2","MSH6","PMS2")), collapse = " OR "), ")")
  paste0("( (", is_msi, " AND NOT ", is_mss, " AND ", inl(scol, msi_pos), ")",
         " OR (", is_mmr, " AND ", inl(scol, mmr_def), ")",
         " OR (", is_prot, " AND ", inl(scol, prot_loss), ") )")
}

# Notes gate. t_patient has two flags: NOTES_ELIGIBLE (the source could supply notes) and HAS_NOTES

# Cohort gate: notes for every cohort, plus the claims flags for 2a/3.
rdq1_cohort_pts <- function(con, cohort) {
  p <- mc_tbl(con, "patient")
  if (RDQ1_REQUIRE_NOTES)  p <- p |> dplyr::filter(has_notes == "Y")
  if (cohort == "2a")      p <- p |> dplyr::filter(market_clarity == "Y", integrated == "Y")

# Claims-lab dMMR/MSI-H test (raw SQL on t_clm_lab_results). rslt_nbr is useless (all 0.00) and
# rslt_txt is mostly placeholders, so the rule keys off tst_desc: an MSI test that is POSITIVE/
# ABNORMAL, or an MMR protein IHC test that is NOT EXPRESSED/NOT DETECTED. Mutation/variant tests are
# excluded (there "not detected" means the opposite).
rdq1_clm_lab_msi_mmr <- function() {
  msi <- paste0("(lower(tst_desc) RLIKE 'microsatellite|msi' ",
                "AND lower(tst_desc) NOT RLIKE 'methylation|borrelia|hermsii|mutation|variant|gene|without|w/o' ",
                "AND upper(rslt_txt) IN ('POSITIVE','ABNORMAL'))")
  mmr <- paste0("(lower(tst_desc) RLIKE 'mlh1|msh2|msh6|pms2' ",
                "AND lower(tst_desc) RLIKE 'ihc|interp' ",
                "AND upper(rslt_txt) IN ('NOT EXPRESSED','NOT DETECTED'))")
  paste0("(", msi, " OR ", mmr, ")")
}

# Step 1 — colon surgery. Returns every qualifying surgery date per patient (not just the first);
# the orchestrator picks the index. use_claims adds t_clm_* for 2a/3.
rdq1_surgery <- function(con, use_claims = FALSE) {
  ehr <- mc_tbl(con, "procedure") |>
    dplyr::filter(proc_code %in% RDQ1_SURG_CODES,
                  proc_date >= RDQ1_STUDY_START, proc_date <= RDQ1_STUDY_END) |>
    dplyr::transmute(ptid, sdate = proc_date)
  src <- ehr
  if (use_claims) {
    # CPT/HCPCS live in med_services.proc_cd; ICD-10-PCS in med_procedure.proc.
    cpt <- mc_tbl(con, "clm_med_services") |>
      dplyr::filter(proc_cd %in% c(RDQ1_SURG_CPT, RDQ1_SURG_HCPCS),
                    fst_dt >= RDQ1_STUDY_START, fst_dt <= RDQ1_STUDY_END) |>
      dplyr::transmute(ptid, sdate = fst_dt)
    pcs <- mc_tbl(con, "clm_med_procedure") |>
      dplyr::filter(proc %in% RDQ1_SURG_PCS,
                    fst_dt >= RDQ1_STUDY_START, fst_dt <= RDQ1_STUDY_END) |>
      dplyr::transmute(ptid, sdate = fst_dt)
    src <- dplyr::union_all(dplyr::union_all(ehr, cpt), pcs)
  }
  # Keep all surgery dates (don't reduce to the min). The orchestrator picks the index surgery.
  src |> dplyr::transmute(ptid, surgery_date = sdate) |> dplyr::distinct()
}

# Step 2 — colon dx. Returns every colon dx (ptid + date), bounded to the study window. The
# orchestrator keeps only dx in the 183 days before surgery and takes the earliest one. Bounding to
# the study window stops old claims history (e.g. 2007) from leaking in. 1b adds note-based dx;
# use_claims adds claim dx.
rdq1_colon_dx <- function(con, variant, use_claims = FALSE) {
  ehr <- mc_tbl(con, "diagnosis") |>
    dplyr::filter(diagnosis_cd_type == "ICD10", diagnosis_cd %in% RDQ1_DX_ICD,
                  diag_date >= RDQ1_STUDY_START, diag_date <= RDQ1_STUDY_END) |>
    dplyr::transmute(ptid, dx_date = diag_date)
  src <- ehr
  if (variant == "1b") {
    eo <- mc_tbl(con, "onc_neoplasm_histology") |>
      dplyr::filter(dbplyr::sql(rdq1_like_any("neoplasm_type", RDQ1_COLON_NEO_SUBSTR)),
                    neoplasm_qualifier == "actual",
                    note_date >= RDQ1_STUDY_START, note_date <= RDQ1_STUDY_END) |>
      dplyr::transmute(ptid, dx_date = note_date)
    src <- dplyr::union_all(src, eo)
  }
  if (use_claims) {
    cd <- mc_tbl(con, "clm_med_diagnosis") |>
      dplyr::filter(diag %in% RDQ1_DX_ICD,
                    fst_dt >= RDQ1_STUDY_START, fst_dt <= RDQ1_STUDY_END) |>
      dplyr::transmute(ptid, dx_date = fst_dt)
    src <- dplyr::union_all(src, cd)
  }
  src   # not reduced here; the orchestrator applies the surgery window and takes the earliest dx
}

# Step 3 — stage T1-4N1-2 or T4N0. 1a = G-codes; 1b adds onc_tnm + a node fallback; use_claims adds
# claim G-codes (claims have no structured TNM). All sources bounded to the study window.
rdq1_stage_ok <- function(con, variant, use_claims = FALSE, neo_keys = NULL) {
  g <- mc_tbl(con, "procedure") |>
    dplyr::filter(proc_code %in% RDQ1_STAGE_G_QUALIFY,
                  proc_date >= RDQ1_STUDY_START, proc_date <= RDQ1_STUDY_END) |>
    dplyr::distinct(ptid)
  if (use_claims) {
    gc <- mc_tbl(con, "clm_med_services") |>
      dplyr::filter(proc_cd %in% RDQ1_STAGE_G_QUALIFY,
                    fst_dt >= RDQ1_STUDY_START, fst_dt <= RDQ1_STUDY_END) |>
      dplyr::distinct(ptid)
    g <- dplyr::union(g, gc)
  }
  if (variant == "1a") return(g)
  # onc_tnm rows, tied to a colon tumor. PROD passes no neo_keys, so we use the else branch: any of
  # the patient's colon tumors (patient-level). neo_keys (the exact episode tumor by ptid+key) is kept
  # only so the Q6b diagnostic can compare the old tie; see the orchestrator note (Q6b).
  # (rename n -> n_val; `n` clashes with dplyr::n(). We read the first char of T and N.)
  tnm <- mc_tbl(con, "onc_tnm") |>
    dplyr::filter(note_date >= RDQ1_STUDY_START, note_date <= RDQ1_STUDY_END)   # study window
  tnm <- if (is.null(neo_keys))
    dplyr::semi_join(tnm, rdq1_colon_neo_keys(con), by = "neoplasm_histology_key")
  else
    dplyr::semi_join(tnm, neo_keys, by = c("ptid", "neoplasm_histology_key"))
  tnm <- tnm |>
    dplyr::rename(n_val = n) |>
    dplyr::mutate(t1 = substr(t, 1, 1), n1 = substr(n_val, 1, 1))
  rule_main <- tnm |>
    dplyr::filter((t1 %in% c("1","2","3","4") & n1 %in% c("1","2")) |
                  (t1 == "4" & n1 == "0")) |> dplyr::distinct(ptid)
  tnm_nabsent <- tnm |>   # N missing (null/empty/Nx) can still qualify via a positive node
    dplyr::filter((is.na(n_val) | n_val == "" | tolower(n_val) == "x") &
                  t1 %in% c("1","2","3","4")) |> dplyr::distinct(ptid)
  # Positive node only. Use the narrative, not lymph_numeric, which also counts negative/examined nodes.
  ln_pos <- mc_tbl(con, "onc_lymph_node") |>
    dplyr::filter(dbplyr::sql("lower(lymph_narrative) LIKE '%positive lymph node%'"),
                  note_date >= RDQ1_STUDY_START, note_date <= RDQ1_STUDY_END) |>
    dplyr::distinct(ptid)
  rule_fallback <- dplyr::inner_join(tnm_nabsent, ln_pos, by = "ptid")
  dplyr::union(dplyr::union(g, rule_main), rule_fallback)   # additive: codes + EO
}

# Step 4 helper — earliest mets per patient. All sources bounded to the study window (same reason as
# step 2). 1b adds enriched-onc mets; use_claims adds claim mets.
rdq1_mets <- function(con, variant, use_claims = FALSE) {
  m_icd <- mc_tbl(con, "diagnosis") |>
    dplyr::filter(diagnosis_cd_type == "ICD10", substr(diagnosis_cd, 1, 3) %in% RDQ1_METS_ICD3,
                  diag_date >= RDQ1_STUDY_START, diag_date <= RDQ1_STUDY_END) |>
    dplyr::transmute(ptid, mets_date = diag_date)
  m_g <- mc_tbl(con, "procedure") |>
    dplyr::filter(proc_code %in% RDQ1_METS_G,
                  proc_date >= RDQ1_STUDY_START, proc_date <= RDQ1_STUDY_END) |>
    dplyr::transmute(ptid, mets_date = proc_date)
  src <- dplyr::union_all(m_icd, m_g)                       # ICD + G-codes -> 1a AND 1b
  if (use_claims) {
    cm_icd <- mc_tbl(con, "clm_med_diagnosis") |>
      dplyr::filter(substr(diag, 1, 3) %in% RDQ1_METS_ICD3,
                    fst_dt >= RDQ1_STUDY_START, fst_dt <= RDQ1_STUDY_END) |>
      dplyr::transmute(ptid, mets_date = fst_dt)
    cm_g <- mc_tbl(con, "clm_med_services") |>
      dplyr::filter(proc_cd %in% RDQ1_METS_G,
                    fst_dt >= RDQ1_STUDY_START, fst_dt <= RDQ1_STUDY_END) |>
      dplyr::transmute(ptid, mets_date = fst_dt)
    src <- dplyr::union_all(dplyr::union_all(src, cm_icd), cm_g)
  }
  if (variant == "1b") {
    # Mets is patient-level, not tied to the colon tumor: criterion 4 excludes any C77-79, so tying
    # it to the colon key would be narrower than the RDQ asks. Keep 'actual' + 'current' (drop negated
    # and history mentions). Anchor on note_date; metastasis_dx_date is mostly null/partial.
    m_loc <- mc_tbl(con, "onc_metastatic_location") |>
      dplyr::filter(mets_qualifier == "actual", mets_temporal_status == "current",
                    note_date >= RDQ1_STUDY_START, note_date <= RDQ1_STUDY_END) |>
      dplyr::transmute(ptid, mets_date = note_date)
    m_tnm <- mc_tbl(con, "onc_tnm") |>
      dplyr::filter(substr(m, 1, 1) == "1",
                    note_date >= RDQ1_STUDY_START, note_date <= RDQ1_STUDY_END) |>
      dplyr::transmute(ptid, mets_date = note_date)
    src <- dplyr::union_all(dplyr::union_all(src, m_loc), m_tnm)
  }
  src |> dplyr::group_by(ptid) |>
    dplyr::summarise(mets_date = min(mets_date, na.rm = TRUE), .groups = "drop")
}

# Step 5 — dMMR/MSI-H. 1a = t_biomarker + t_lab; 1b adds t_onc_biomarker; use_claims adds
# t_clm_lab_results.
rdq1_biomarker <- function(con, variant, use_claims = FALSE) {
  nlp <- mc_tbl(con, "biomarker") |>
    dplyr::filter(dbplyr::sql(rdq1_dmmr_msi_predicate("biomarker", "biomarker_status"))) |>
    dplyr::distinct(ptid)
  lab <- mc_tbl(con, "lab") |>   # t_lab uses its own vocab (LOST/INTACT/...); pass RDQ1_LAB_* sets
    dplyr::filter(dbplyr::sql(rdq1_dmmr_msi_predicate("test_name", "test_result",
                   RDQ1_LAB_MSI_POS, RDQ1_LAB_MMR_DEF, RDQ1_LAB_PROT_LOSS))) |>
    dplyr::distinct(ptid)
  out <- dplyr::union(nlp, lab)
  if (variant == "1b") {
    onc <- mc_tbl(con, "onc_biomarker") |>
      dplyr::filter(dbplyr::sql(rdq1_dmmr_msi_predicate("biomarker", "narrative_result"))) |>
      dplyr::distinct(ptid)
    out <- dplyr::union(out, onc)
  }
  if (use_claims) {   # small claims-lab arm (calibrated tst_desc-conditional rule)
    clm <- mc_tbl(con, "clm_lab_results") |>
      dplyr::filter(dbplyr::sql(rdq1_clm_lab_msi_mmr())) |>
      dplyr::distinct(ptid)
    out <- dplyr::union(out, clm)
  }
  out
}

# Step 6 — IO use (ptid + io_date; the date window is applied in the orchestrator). 1b adds
# t_onc_medications; use_claims adds t_clm_rx (PAID) + t_clm_med_services (J-codes / NDC).
rdq1_io <- function(con, variant, use_claims = FALSE) {
  proc <- mc_tbl(con, "procedure") |>
    dplyr::filter(proc_code %in% RDQ1_IO_JCODE) |> dplyr::transmute(ptid, io_date = proc_date)
  # admin_date is often null in t_administrations, so use coalesce(admin_date, order_date).
  adm <- mc_tbl(con, "administrations") |>
    dplyr::filter(dbplyr::sql(rdq1_io_predicate("generic_desc"))) |>
    dplyr::transmute(ptid, io_date = dplyr::coalesce(admin_date, order_date))
  presc <- mc_tbl(con, "prescription") |>
    dplyr::filter(dbplyr::sql(rdq1_io_predicate("generic_desc"))) |>
    dplyr::transmute(ptid, io_date = rxdate)
  io <- dplyr::union_all(dplyr::union_all(proc, adm), presc)
  if (variant == "1b") {
    onc <- mc_tbl(con, "onc_medications") |>   # no ndc column here -> include_ndc = FALSE
      dplyr::filter(dbplyr::sql(rdq1_io_predicate(c("generic_desc", "drug_name"), include_ndc = FALSE)),
                    # keep only the non-claim sources so cohort 1 stays claims-free
                    data_source %in% c("proc","provider_notes","rx_adm","rx_presc")) |>
      dplyr::transmute(ptid, io_date = action_date)
    io <- dplyr::union_all(io, onc)
  }
  if (use_claims) {
    # clm_rx: match on generic name or NDC; PAID only (rejected/reversed were not dispensed).
    rx <- mc_tbl(con, "clm_rx") |>
      dplyr::filter(transaction_type == "PAID",
                    dbplyr::sql(rdq1_io_predicate("gnrc_nm"))) |>
      dplyr::transmute(ptid, io_date = fill_dt)
    # med_services: infused IO via J-code or NDC. paid_status is almost all null, so we don't filter it.
    svc <- mc_tbl(con, "clm_med_services") |>
      dplyr::filter(proc_cd %in% RDQ1_IO_JCODE | ndc %in% RDQ1_IO_NDC) |>
      dplyr::transmute(ptid, io_date = fst_dt)
    io <- dplyr::union_all(dplyr::union_all(io, rx), svc)
  }
  io
}

# ============================================================================
# 4. ORCHESTRATOR
# ============================================================================
rdq1_attrition_table <- function(con, variant = c("1a", "1b"), cohort = c("1", "2a", "3"),
                                  materialize = FALSE, replace = FALSE, verbose = TRUE) {
  variant <- match.arg(variant); cohort <- match.arg(cohort)
  uc <- cohort != "1"                       # cohorts 2a/3 add claims ascertainment

  dx   <- rdq1_colon_dx(con, variant, uc)
  mets <- rdq1_mets(con, variant, uc)

  # spine: surgeries, gated to this cohort's patients
  s1 <- rdq1_surgery(con, uc) |>
    dplyr::semi_join(rdq1_cohort_pts(con, cohort), by = "ptid")

  # Index = the earliest colectomy that has a colon dx in its 183-day window. Pair each surgery with
  # the dx, keep pairs inside the window, take the earliest such surgery, and its earliest dx. This
  # stops an early unrelated colectomy from pinning the index and dropping the patient. Step-1 count
  # (distinct ptid) is unchanged; step-2 can only go up.
  pairs <- s1 |>
    dplyr::inner_join(dx, by = "ptid") |>
    dplyr::filter(dx_date <= surgery_date,
                  datediff(surgery_date, dx_date) <= RDQ1_DX_WINDOW_DAYS)
  idx_surg <- pairs |>                       # earliest dx-linked surgery = index
    dplyr::group_by(ptid) |>
    dplyr::summarise(surgery_date = min(surgery_date, na.rm = TRUE), .groups = "drop")
  s2 <- pairs |>
    dplyr::inner_join(idx_surg, by = c("ptid", "surgery_date")) |>
    dplyr::group_by(ptid, surgery_date) |>
    dplyr::summarise(colon_dx_date = min(dx_date, na.rm = TRUE), .groups = "drop")

  # Staging is tied to ANY of the patient's colon tumors (patient-level colon tie), not to the exact
  # episode neoplasm_histology_key. The tighter Optum-4.3.2 episode-key tie was tested (Q6b) and
  # dropped ~5.9x of genuinely-staged patients: the same tumor gets multiple neoplasm_histology_keys
  # (pre-op clinical note vs surgical-pathology record), and onc_tnm sits on the pathology key while
  # the pre-op-note key seeded the tie. For the ~99% single-colon-primary patient this is the same
  # tumor. G-codes and the node fallback are already patient-level.
  s3 <- s2 |> dplyr::semi_join(rdq1_stage_ok(con, variant, uc), by = "ptid")

  s4 <- s3 |>
    dplyr::left_join(mets, by = "ptid") |>
    dplyr::filter(is.na(mets_date) | mets_date >= surgery_date)

  s5 <- s4 |> dplyr::semi_join(rdq1_biomarker(con, variant, uc), by = "ptid")

  s6 <- s5 |>
    dplyr::inner_join(rdq1_io(con, variant, uc), by = "ptid") |>
    # io_date >= colon_dx_date already keeps IO on/after 2020 (dx is study-bounded); cap the top end
    # too so every event source is inside [2020, 2025].
    dplyr::filter(io_date >= colon_dx_date, io_date <= RDQ1_STUDY_END,
                  is.na(mets_date) | io_date < mets_date) |>
    dplyr::distinct(ptid, surgery_date, colon_dx_date, mets_date)

  steps  <- list(s1, s2, s3, s4, s5, s6)
  labels <- c("1. Colon cancer surgery",
              "2. Newly diagnosed colon cancer within 183d prior to surgery",
              "3. Stage T1-4N1-2 or T4N0",
              "4. No metastatic diagnosis prior to surgery",
              "5. dMMR+ or MSI-H",
              "6. IO use after dx and prior to metastatic diagnosis")

  n <- integer(length(steps))
  for (i in seq_along(steps)) {
    n[i] <- n_ptid(steps[[i]])
    if (verbose) message(sprintf("[c%s %s] step %d  n=%s", cohort, variant, i,
                                 format(n[i], big.mark = ",")))
  }

  out <- data.frame(
    cohort = cohort, variant = variant, step = seq_along(steps), criterion = labels, n = n,
    pct_step1 = round(100 * n / n[1], 1),
    pct_prev  = round(100 * n / c(n[1], head(n, -1)), 1),
    n_display = mc_mask(n), stringsAsFactors = FALSE)

  if (materialize) {
    # createInPersonalSchema() uses the global `con` and writes to osk02156. Make sure con is set.
    createInPersonalSchema(s6, paste0("rdq1_c", cohort, "_", variant), replace = replace)
  }
  out
}

# Run the requested cohorts x variants and stack the attrition tables (default = all 6).
rdq1_run <- function(con, cohorts = RDQ1_COHORTS, variants = RDQ1_VARIANTS,
                     materialize = FALSE, replace = FALSE) {
  grid <- expand.grid(cohort = cohorts, variant = variants,
                      KEEP.OUT.ATTRS = FALSE, stringsAsFactors = FALSE)
  do.call(rbind, Map(function(co, va)
    rdq1_attrition_table(con, va, co, materialize = materialize, replace = replace),
    grid$cohort, grid$variant))
}

# ============================================================================
# 5. VALIDATION HELPER — list candidate biomarker values to eyeball
# ============================================================================
rdq1_biomarker_values <- function(con, n = 200) {
  list(
    lab = mc_tbl(con, "lab") |>
      dplyr::filter(dbplyr::sql(rdq1_like_any("test_name", RDQ1_BIOMARKER_NAME_SUBSTR))) |>
      dplyr::count(test_name, test_result, sort = TRUE) |> head(n) |> dplyr::collect(),
    nlp_biomarker = mc_tbl(con, "biomarker") |>
      dplyr::filter(dbplyr::sql(rdq1_like_any("biomarker", RDQ1_BIOMARKER_NAME_SUBSTR))) |>
      dplyr::count(biomarker, biomarker_status, sort = TRUE) |> head(n) |> dplyr::collect(),
    onc_biomarker = mc_tbl(con, "onc_biomarker") |>
      dplyr::filter(dbplyr::sql(rdq1_like_any("biomarker", RDQ1_BIOMARKER_NAME_SUBSTR))) |>
      dplyr::count(biomarker, narrative_result, sort = TRUE) |> head(n) |> dplyr::collect())
}

# ============================================================================
# 6. Rscript entry point
# ============================================================================
# `Rscript rdq1_cohort1.R` connects and runs the full grid (all 3 cohorts x 2 variants).
# When the file is source()d (interactively, or by the v2 check) this block does nothing —
# sys.nframe() is 0 only when the file is the top-level script, >0 when sourced.
# Set RDQ1_MATERIALIZE=0 to skip persisting the step-6 tables to the personal schema (default: on).
if (sys.nframe() == 0L && !interactive()) {
  con <- mc_connect()
  mat <- !identical(Sys.getenv("RDQ1_MATERIALIZE", "1"), "0")
  if (mat && !exists("createInPersonalSchema")) {   # don't lose a good run at the persistence step
    message("createInPersonalSchema() is not loaded — running WITHOUT materialize. ",
            "Load the prod personal-schema helper (or set RDQ1_MATERIALIZE=0) to silence this.")
    mat <- FALSE
  }
  res <- rdq1_run(con, materialize = mat, replace = mat)
  # per-step counts already streamed to stderr; print the stacked table to stdout
  print(res[, c("cohort", "variant", "step", "n", "n_display", "pct_step1", "pct_prev")],
        row.names = FALSE)
}



# ============================================================================
# rdq1_check_v2_staging.R — CHECK SCRIPT (not the prod deliverable).
#
# Purpose: test reading #2 of the RDQ form. The form does NOT tag step 3 (Stage)
# or step 5 (dMMR/MSI-H) as "[from EHR]" (steps 1/2/4/6 are). Structured codes
# carry no TNM: the qualifying G-codes G9085/G9086 cover ~7-14 patients total, so
# the 1a funnel dies at step 3. Reading #2 says staging + biomarker should come
# from enriched oncology (t_onc_tnm / t_onc_biomarker) in BOTH tables, and 1a vs
# 1b should differ only on the [from EHR] steps (1, 2, 4, 6).
#
# This script leaves rdq1_cohort1.R alone. It reuses every builder and just swaps
# the step-3 and step-5 calls to force the enriched-onc arm ("1b") for all variants.
#
# Run — either works:
#   Rscript R/rdq1_check_v2_staging.R    # standalone: sources the main file, then runs the v2 grid
#   # or interactively:
#   source("R/rdq1_cohort1.R"); source("R/rdq1_check_v2_staging.R"); rdq1_run_v2(mc_connect())
# Compare the step-3 / step-5 rows against the prod rdq1_run(con).
# ============================================================================

# Make sure the main pipeline is loaded. If the builders aren't defined yet (e.g. run via Rscript),
# source rdq1_cohort1.R from next to THIS script. Sourcing it does NOT trigger the prod run — the
# main file's entry point is guarded by sys.nframe().
if (!exists("rdq1_attrition_table") || !exists("rdq1_stage_ok")) {
  .args <- commandArgs(trailingOnly = FALSE)
  .fa   <- sub("^--file=", "", .args[grep("^--file=", .args)])
  .here <- if (length(.fa)) dirname(normalizePath(.fa)) else if (dir.exists("R")) "R" else "."
  .main <- file.path(.here, "rdq1_cohort1.R")
  if (!file.exists(.main)) stop("Cannot find rdq1_cohort1.R next to this script; source it first.")
  source(.main)
}

# Same orchestrator as prod, with two lines changed: step 3 and step 5 always use
# the enriched-onc arm ("1b") regardless of the table variant. Steps 1/2/4/6 keep
# the real variant, so 1a still excludes enriched onc for surgery/dx/mets/IO.
rdq1_attrition_table_v2 <- function(con, variant = c("1a", "1b"), cohort = c("1", "2a", "3"),
                                    materialize = FALSE, replace = FALSE, verbose = TRUE) {
  variant <- match.arg(variant); cohort <- match.arg(cohort)
  uc <- cohort != "1"

  dx   <- rdq1_colon_dx(con, variant, uc)
  mets <- rdq1_mets(con, variant, uc)

  s1 <- rdq1_surgery(con, uc) |>
    dplyr::semi_join(rdq1_cohort_pts(con, cohort), by = "ptid")

  pairs <- s1 |>
    dplyr::inner_join(dx, by = "ptid") |>
    dplyr::filter(dx_date <= surgery_date,
                  datediff(surgery_date, dx_date) <= RDQ1_DX_WINDOW_DAYS)
  idx_surg <- pairs |>
    dplyr::group_by(ptid) |>
    dplyr::summarise(surgery_date = min(surgery_date, na.rm = TRUE), .groups = "drop")
  s2 <- pairs |>
    dplyr::inner_join(idx_surg, by = c("ptid", "surgery_date")) |>
    dplyr::group_by(ptid, surgery_date) |>
    dplyr::summarise(colon_dx_date = min(dx_date, na.rm = TRUE), .groups = "drop")

  # v2: staging always uses the enriched-onc arm ("1b": t_onc_tnm + G-codes + node fallback),
  # patient-level colon tie (same as prod since Q6b). This is the change vs the 1a prod path for step 3.
  s3 <- s2 |> dplyr::semi_join(rdq1_stage_ok(con, "1b", uc), by = "ptid")

  s4 <- s3 |>
    dplyr::left_join(mets, by = "ptid") |>
    dplyr::filter(is.na(mets_date) | mets_date >= surgery_date)

  # v2: biomarker always uses the enriched-onc arm (adds t_onc_biomarker). Only change for step 5.
  s5 <- s4 |> dplyr::semi_join(rdq1_biomarker(con, "1b", uc), by = "ptid")

  s6 <- s5 |>
    dplyr::inner_join(rdq1_io(con, variant, uc), by = "ptid") |>
    dplyr::filter(io_date >= colon_dx_date, io_date <= RDQ1_STUDY_END,
                  is.na(mets_date) | io_date < mets_date) |>
    dplyr::distinct(ptid, surgery_date, colon_dx_date, mets_date)

  steps  <- list(s1, s2, s3, s4, s5, s6)
  labels <- c("1. Colon cancer surgery",
              "2. Newly diagnosed colon cancer within 183d prior to surgery",
              "3. Stage T1-4N1-2 or T4N0 (enriched onc)",
              "4. No metastatic diagnosis prior to surgery",
              "5. dMMR+ or MSI-H (enriched onc)",
              "6. IO use after dx and prior to metastatic diagnosis")

  n <- integer(length(steps))
  for (i in seq_along(steps)) {
    n[i] <- n_ptid(steps[[i]])
    if (verbose) message(sprintf("[c%s %s v2] step %d  n=%s", cohort, variant, i,
                                 format(n[i], big.mark = ",")))
  }

  out <- data.frame(
    cohort = cohort, variant = variant, step = seq_along(steps), criterion = labels, n = n,
    pct_step1 = round(100 * n / n[1], 1),
    pct_prev  = round(100 * n / c(n[1], head(n, -1)), 1),
    n_display = mc_mask(n), stringsAsFactors = FALSE)

  if (materialize) {
    createInPersonalSchema(s6, paste0("rdq1_v2_c", cohort, "_", variant), replace = replace)
  }
  out
}

# Run the requested cohorts x variants under v2 (default = all 6).
rdq1_run_v2 <- function(con, cohorts = RDQ1_COHORTS, variants = RDQ1_VARIANTS,

  grid <- expand.grid(cohort = cohorts, variant = variants,

    grid$cohort, grid$variant))
