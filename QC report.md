# QC report — GIST RWDP dataset program vs specification (v3)

**New in v3:**
- **Variable QC:** a variable-by-variable trace of all 116 spec variables (plus 9 study periods/parameters) through to the final dataset. Each one was built by one agent and re-traced independently by a second, which corrected 43 first-pass rows.
- **Final-dataset column census:** all 179 fixed columns traced.
- **Third critique:** the other reviewer's critique of v2 was checked point by point; 9 of 10 qualifications were accepted, and one needed no change.
- **Sweep:** 25 further claims were narrowed the same way, each after an independent check.
- **No more truncation:** v2 cut long text with "…"; v3 prints everything in full.

## Bottom line

The program is not ready to release.

- **Variables:** every spec variable is accounted for. 109 of the 116 reach the final dataset, 4 of them under a different name. 7 do not reach it at all:
  - LAST_CLINIC_NOTE_DT is dropped before output.
  - F_ADV_NEXT_LOT is not implemented.
  - NEXT_LOT_START_DT, SECOND_SUBSEQ_LOT_START_DT, TTDDT, TTNTDT and TSSTDT exist only inside other calculations.
- **Derivations (116 variables):** 46 match the spec, 47 deviate, 14 depend on data we couldn't see, 7 are partial, 1 is unclear in the spec, and 1 is not implemented. 41 variables use text labels or different codes from the spec's coding.
- **Study periods and parameters (9):** 4 match. STUDY_PD's 01-Jan-2011 bound is never applied, and DATA_CUTOFF_DT is only partly applied (RC-15).
- **Code:** 39 distinct root causes: **1 critical, 3 high, 22 medium, 13 low**.

## Fix first

1. **RC-01 (critical) — OS is NA for censored patients who have no mortality-table row** (QC-001). Affected: patients with ID3MOSFU = 1, a calculable follow-up end (FUED not null), and no Enhanced_Mortality_V2 row.
   - Cause: `dthfl` is computed inside the mortality subquery and left-joined (lines 1278–1300), so unmatched patients carry `dthfl = NULL`. The censoring branch tests `dthfl == 0` (line 2360) and falls to NA. NULL only becomes 0 at line 2426, after OS.
   - Patients whose mortality row has a NULL death date get `dthfl = 0` and a correct OS. Enhanced_Mortality_V2 normally holds decedents only, so in practice this is nearly all censored patients; confirm with a coverage count.
   - Fix: `coalesce(dthfl, 0)` right after the join.
2. **RC-03 (high) — PFSFL counts deaths on or before INDEXDT+14 as events** (QC-005). The spec's own PFSFL definition and note conflict on whether those patients are censored or excluded (QC-054).
3. **RC-04 (high) — PFSDT is NA for censored patients** instead of LAST_CLINIC_NOTE_DT (QC-006). PFS uses the clinic-note date directly, so the PFS duration is right but PFSDT doesn't match it.
4. **RC-02 (high) — spec variables missing from or misnamed in the final dataset** (QC-003, QC-004, QC-065):
   - LAST_CLINIC_NOTE_DT is dropped.
   - Six date/flag variables are never output.
   - `inityr`, `birthyear` and `progressiondate` don't carry their spec names.
